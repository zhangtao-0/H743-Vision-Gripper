# 多层标签、资料库与自主训练

本轮按用户2026-10-24明确授权建立并实际下载、短训练。以前05文档逐项批准的门槛在本轮“首批公开素材、一个小权重、复用现有CPU训练环境”的范围内已获得新授权；不延伸到付费服务、上传数据、GPU驱动更换或硬件动作。

## 1. 资料放哪里

[Library资料库](../Library/README.md)是统一入口。物体照片不按本轮任务分散复制；原件目录不可覆盖。索引与许可→原件→标签本体→派生标注→冻结数据版本→模型注册→测试基准→抓取规则，构成可追溯链。

已下载TACO48张真实图，杯子/箱类/瓶子各选16张，原图约74.66MB。图片可同时有多类物体，所以训练时保留每张图中全部目标实例。原始60类字典及全量标注保留，当前目标子集中82实例派生为cup/box/bottle；细类如Paper cup、Drink carton仍逐实例可查，未被新类别覆盖。

原图来源和许可见Library/00_索引与许可/taco_downloads.json，注释来自官方annotations。TACO官网明示缺少单图许可条目时默认CC BY4.0；标注CC BY4.0，程序代码MIT。其他数据源没有明确许可时只登记，不自动混入训练。MVTec/GraspNet暂留来源与限制，不下载大包。

## 2. 标签是证据集合，不是固定一棵类别树

| 层 | 例子 | 如何得到 |
|---|---|---|
| 原始语义 | TACO/Paper_cup、Drink_carton | 原数据标注，保留native ID |
| 通用语义 | cup、box、bottle、未来bracket | 模型输出或有记录的类别映射 |
| 几何 | elongated_2d、concave_2d；以后cylinder/rectangular | Mask像素几何；三维必须另有测量 |
| 材料 | glass、paper、plastic | 实测/人工核对，或明确标inferred的类别弱先验 |
| 状态 | fragile、contains_liquid、deformed | 独立视觉/传感器/人工证据，不由杯子类别强行推断 |
| 部件 | handle_present、rim、body | 部件分割/检测及独立scope |
| 安全/可执行性 | hot、human_contact、标定/行程/力限 | 实测状态与机构控制反馈 |

每条标签包含id、confidence、source、scope（可选）和unknown状态。没有固定标签数量；可以把多个模型/人工/传感器的结果一起提交。不同部件可有不同材料，不强制把复合对象只归一类。未知不等于否定。

当前真实训练网络只学习cup/box/bottle三个通用语义类及Mask；材料/质量/温度/内容物没有被训练出来。prediction_tags.py已把实际模型预测接到规则器，派生2D几何，不伪造三维圆柱或摩擦系数。源标注富标签是单独sidecar，不冒充网络已经学会所有属性。

## 3. 叠加、优先级、组合评判

1. 校验置信度和证据来源，去重，防止同一标签重复100次加分。
2. 对同一scope内互斥属性，比证据等级：measured > human_verified > source_annotation > model > inferred。同等级矛盾则拒绝，不偷偷挑一个。
3. 单层语义也有基础候选：cup/bottle→侧向包络，box→对向面夹持。没有其他标签时仍能输出候选。
4. 几何等标签给候选叠加权重；组合匹配时增加候选或附加约束。例如cup+handle可提出把手支撑，但必须有把手空间实测。
5. 高优先级禁用/安全约束先起作用，低级评分不能覆盖禁用。易碎+把手禁止把手方案，装液体加保持直立/禁止翻转；热/人体接触/电危险直接拒绝。
6. 若候选分数并列、缺标定/机构几何/工作区/反馈等，输出拒绝原因。分数只是策略排序，不是抓稳概率。

[杯子单层示例](../Library/07_抓取规则/cup_only/output.json)和[易碎装液体带把手杯子](../Library/07_抓取规则/fragile_cup_handle/output.json)都已真实运行。规则版本在Library/07_抓取规则/rules.json；接口接受任意数量标签，未知命名空间仍保留。

即使所有规划前提输入为已核实，当前模块仍输出DRY_RUN、grasp_valid=false、hardware_commands_sent=false；没有电机发送接口。今后在完成真实三指规划/执行验收后再增加独立的执行路径。

## 4. 自动训练怎么用

双击Vision_AI/自动检查与训练.cmd，或从H743根目录：

```powershell
& .\Vision_AI\.venv\Scripts\python.exe .\Vision_AI\training\autopilot.py
```

入口会校验冻结数据、图片/标签/权重哈希、跨split精确重复，读取配置中的数据版本，选择已具备的本地CPU训练环境，按预算训练/评价并登记候选。标签和图像变了却复用旧manifest会拒绝；正确增加数据必须生成新版本。相同数据、权重、配方和worker重复运行返回up_to_date，不浪费算力；有OS锁防止重复同时启动。

本轮已跑2epoch、160输入、batch2、CPU线程配置4，单任务20分钟上限，48图；配置在configs/autopilot.json。模型保存和test评价已完成，日志、CSV、JSON预测、权重哈希自动归档，不要求你手动管理文件。学习环境没有torch时，训练阶段只读使用Host已有CPU环境，不改它的包。未来GPU包仍需单独准备。

当前是一次触发式工作流，未创建定时/常驻后台服务。后续你提供新物体/照片或提出目标，我可继续负责源登记、分层标签、分组、训练、比较与模型版本；不要求你手动挑权重或调每个训练参数。

## 5. 已查到的自动化方法

Ultralytics原生train可完成训练，原生tune支持多轮超参数搜索；官方文档还讨论Ray Tune。它们解决的是训练/调参执行，不会自动保证标签真、测试独立、三指可达或模型能抓稳。

本项目先用受控包装器把数据审计、训练、验证、固定test、模型台账串起来。默认不启用300轮式搜索；小样本与CPU阶段无限调参容易浪费资源和过拟合。将来有足够的真实训练/val数据，再在同一个固定test外进行少量候选搜索，按val选择候选，test只用于选定后报告。

## 6. 本次模型结果怎样理解

公开小数据30train/9val/9test，test共11实例。Mask mAP50=0.3733，mAP50-95=0.2967；conf0.25时仅1张test图保存2个检测，8张没有检测。精度不足，不能将它写成“已经能识别全部杯子箱子”。更不是H743实拍指标或抓取成功率。

台账登记为challenger_only，champion为空，未发布到旧Host或H743。发布门槛包括真实H743保留集、精度与基线比较；本轮缺H743图且mAP50未达0.5，所以自动拒绝发布。门槛是工程起步值，正式实验需按物体/失误代价调整，不靠降低门槛制造PASS。

faster-coco-eval可选库缺失，自动安装已关闭；保存的是Ultralytics原生指标和预测，尚无第三方评价器交叉验证。初次检查导入Ultralytics创建了默认用户settings文件，后续worker均把配置定向到experiments/ultralytics_local_config；没有安装/升级旧Host依赖。

## 7. 现在缺哪些东西

- 真实L型支架的可靠标注样本：本批是容器素材，没有L型，不能拿杯子强行补成支架。可继续找明确来源或由你拍摄。
- H743自身拍摄的目标、背景与照明，建立固定实拍test；公开自然场景和垃圾物体有域差异。
- 真实三指机构CAD、指尖/开口、位置/力或电流反馈、坐标标定；视觉无法从普通RGB保证质量、摩擦和接触力。
- 若追求有效训练效率，后续准备独立GPU PyTorch环境；这次CPU短任务已跑通，GPU并非流程验证的阻塞。

代码中新增可理解标签时：先确定来源与含义，再在ontology登记命名空间/互斥组，给rules增加组合/优先级与测试。新增学习任务还需要相应真实标签，不能只加一个JSON名字就称模型已学会。原图、标注、固定test和旧模型保留，失败也归档。
