# 本地 Codex 正式任务：视觉抓取零基础学习与可复现研发

你正在协助建立一个**H743 三指机械夹爪的 PC 视觉研究子项目**。用户在计算机视觉和神经网络训练方面为零基础，需要阶段化教学、真实复现和证据链。工程最终研究方向为**多形状工件视觉识别与三指自适应抓取**；第一阶段只使用 PC 上的 OpenCV/YOLO，不触碰实体机械执行。

## 0. 本轮原则和权限

**允许：** 在用户选定的新建 `Vision_AI/` 或独立研究目录内建立隔离环境、源码、测试、教程、实验记录、可复现脚本；在用户批准且网络可用时下载官方依赖和公开权重。优先维护已有目录结构，不擅自大规模重命名。

**禁止：** 擅自修改或清理 `servo/`、受保护的 `H743_BringUp/`、厂家 STM32CubeH7 源码或其他历史工程；修改生产 IAR/STM32 初始化工程；执行未审批的硬件烧录、GPIO 使能或电机动作；删除原始图像、标注原件和固定测试集；不经许可上传数据到公共服务；为了达到指标去修改测试标签。不存在 GPU/数据时必须明确标为未执行，不得伪造训练结果。

## 阶段 A：只读环境与资料审核

1. 检查 Windows、`py -0p`、Python、VS Code、显卡/驱动、可用内存、磁盘、已有 `.venv`，不更改全局环境。
2. 读取本教学包三个 Markdown 和示例源码，核实 `python -m unittest discover -s tests -v` 是否通过。
3. 官方来源优先核对 OpenCV、CVAT、Ultralytics、PyTorch、GraspNet 当前仓库、许可和安装文档；记录 URL、Release/Commit、日期。
4. 形成 `01_环境审计.md` 和 `02_复现准备清单.md`，按“已具备 / 可新建 / 需用户提供 / 暂不需要”分类。

**阶段 A 验收：** 原有工程无修改；工具与硬件条件有真实命令输出；不得因为 GPU 不存在就阻止 CPU 小实验。

## 阶段 B：传统视觉基线

1. 在新 `Vision_AI/` 创建 Python 3.11/3.12 隔离环境（以已安装、受支持的版本为准），安装 OpenCV、NumPy。
2. 执行本教学包 `03_最小可运行演示/`，保存命令、输出 JSON、标记图和测试结果。
3. 用 10–30 张用户自己拍摄的真实工件图替换模拟图（若没有图片，请给出拍摄要求，不要伪造真实样本）。
4. 实现图像读取、HSV/灰度阈值、背景变化实验、轮廓、质心与旋转矩形，提供原图/掩码/检测结果三联对照。
5. 加入误检、漏检、遮挡、曝光异常的分类记录。

**阶段 B 验收：** 代码可重复运行、最小测试通过、局限性清楚写出；输出坐标标记为 Pixel，不直接发送到机械爪。

## 阶段 C：标定与真实数据采集

1. 提供相机标定板规格、拍摄位置及流程说明，建立固定工作台测量坐标系。
2. 在有真实标定图像时运行畸变参数、平面坐标映射及**未参加拟合的点位误差测试**。
3. 建立数据集原件和标注版本控制规则，列出 3 形状 × 1–3 实物的照片采集计划。
4. 按会话、实物 ID、背景/光照分组拆成 train/val/test，避免同一连续场景泄漏。
5. CVAT / YOLO 分割导出后检查每张图像与标签文件数量、类 ID、归一化范围和 Polygon 点数，生成缺失/错误报告。

**阶段 C 验收：** 实际采集与标注证据齐全；未得到数据时只能提供采集脚本和检查器，不能声称训练条件满足。

## 阶段 D：训练并评价目标识别

1. 按 PyTorch 官方说明在独立 `.venv` 中安装兼容版本，不覆盖其他项目。
2. 先跑预训练 YOLO 的少量图片推理，再开展 `epochs=5`、较小输入尺寸的小型训练冒烟测试。
3. 将数据版本、模型权重、许可证、软件/硬件配置、训练命令、随机种子、训练/验证日志保存到 `experiments/run_id/`。
4. 在测试集固定不变的情况下对比：OpenCV、YOLO 检测、YOLO 实例分割；提供每类 Precision、Recall、Mask IoU/mAP 和延迟。
5. 分类整理错误样本，提出一次只改变一个因素的修复实验；先报用户审核再开始耗时大或产生费用的训练。

**阶段 D 验收：** 必须存在运行日志、原始模型输出、版本信息和真实指标；没有满足条件时标记为 BLOCKED/NOT RUN，不得虚构精度。

## 阶段 E：三指抓取规划器（默认 Dry Run）

1. 根据工件 Mask、固定工作台标定、真实指尖几何参数，规划抓取中心、主方向、预开口、接触区域和不可执行原因。
2. 对圆柱/矩形/L 型分别设置候选策略。附带形状尺寸与边界条件测试。
3. 保存候选方案可视化、输入 JSON、判定结果、拒绝原因和算法版本。
4. 所有输出仅用于仿真/可视化，禁止直接操作实物电机。
5. 如用户后续提供夹爪 CAD、量程、力反馈和电源保护资料，再分独立阶段开发实体安全控制。

**阶段 E 验收：** 低置信度、越界、碰撞风险、几何不可达情况均可拒绝；不得仅凭 Mask 声称可抓取 5 kg。

## 阶段 F：H743 联调（需单独授权）

1. 先验证 H743 OV5640 图像能够导出为电脑可查看的原始帧，并测量颜色格式、帧率、时间戳。
2. 只读查看 CubeMX/IAR 的工程配置、内存布局和 DCMI DMA/Cache 一致性，不擅自覆盖 `.ioc` 或工程文件。
3. 定义 Vision→H743 的二进制/JSON 逻辑协议、坐标单位、帧序号、时间戳和错误码，PC 端用 Mock Controller 做协议测试。
4. 使用日志/显示屏观察识别结果，不连接高功率执行器。
5. 只有用户完成急停、限位、失电、驱动器、位置/力检测验收并批准后，另开实体控制阶段。

## 自动化行为规范

- 每阶段先列**需要的本地工具/文件、授权、风险、可复现命令和验收**，完成后直接执行授权范围内的文件任务。
- 非破坏性检查无需每条命令都重复征询；凡涉及付费训练、上传数据、下载大模型、修改保护目录、驱动真实机械动作时必须明确申请批准。
- 遇到错误：先采集 traceback、配置和原始输入，提出最小修复；保留旧版和回滚方式；重新运行之前的测试。
- 用户是视觉零基础，说明须解释术语、每个文件的用途、每一步能看到什么输出、为何需要下一步。
- 不要因为有了一个新算法就重构整套代码；必须通过与上一版的同一测试集比较来证明价值。

## 最终交付标准

每阶段应提供一份 `阶段验收报告.md`：

- 真实环境清单与工具版本；
- 原始输入与数据集身份；
- 本次新建/修改文件清单；
- 执行命令、退出状态、日志位置；
- 通过/失败测试数量；
- 图片/模型输出及哈希（如果适用）；
- 尚未解决的问题、假设、风险与下一阶段条件。

**第一轮只执行阶段 A 与阶段 B 的可完成部分，按教学书向零基础用户解释每个结果。不要自动开展有成本的大规模训练或实体机械实验。**
