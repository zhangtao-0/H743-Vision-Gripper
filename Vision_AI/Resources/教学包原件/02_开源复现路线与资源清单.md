# 视觉抓取开源方案：复现顺序、适配分析与来源清单

更新：2026-10-24。用途：为 `00_H743_机械手视觉` 选择实际可复现、能提供学习价值的开源方案。**不能因为某个仓库使用“Grasp”就假定兼容三指夹爪。**

## 1. 面向当前硬件的优先级

| 方案 | 开源来源 | 复现入门门槛 | 对当前硬件是否合适 | 可得到的成果 | 主要限制 |
|---|---|---|---|---|---|
| **OpenCV 传统视觉** | [OpenCV](https://opencv.org/) / [教程](https://docs.opencv.org/5.0/tutorials/calib3d/camera_calibration_square_chess/camera_calibration_square_chess.html) | 低 | **最适合第一步** | 颜色阈值、轮廓、中心和相机标定 | 光照、背景敏感；抓取需独立规划 |
| **CVAT 数据标注** | [CVAT 社区版](https://github.com/cvat-ai/cvat) / [文档](https://docs.cvat.ai/docs/) | 中 | 适合自采集 RGB 数据 | 框、Polygon、标注审核与导出 | 本地部署可能需要 Docker；云端版需注意隐私与套餐限制 |
| **YOLO 检测/分割** | [Ultralytics](https://github.com/ultralytics/ultralytics) / [Seg](https://docs.ultralytics.com/tasks/segment) | 中 | **推荐正式识别基线** | 可训练对象类别、Mask、推理测试 | 训练需要数据和算力；AGPL-3.0/商业许可需核查 |
| **GraspNet Baseline** | [graspnet-baseline](https://github.com/graspnet/graspnet-baseline) | 高 | 暂不适合直接移植 | 六维抓取姿态学习方法 | 官方示例需要 RGB-D/内参，常见两指夹爪抓取表示与三指不同；CUDA 扩展配置复杂 |
| **PyTorch** | [官方安装](https://pytorch.org/get-started/locally/) | 中 | PC 模型训练框架 | 模型训练/微调与 GPU 加速 | 必须按 Windows/Python/驱动与 GPU 组合安装 |

## 2. 推荐复现的三个可见成果

### R0：OpenCV 三形状定位（立即可做）

**提供的本地演示**：`03_最小可运行演示/`

先生成模拟工件图，再跑 `shape_baseline.py`，输出 `detections.json` 与绘制中心的 `annotated.png`。两个基础测试已经在交付环境通过，完全不需要实体夹爪、摄像头、下载预训练权重或标注数据。

**验收**：识别到三种模拟形状，正确区分图像像素坐标与机械实际坐标。之后替换真实照片，记录光照和反光导致的失败。

### R1：YOLO 官方预训练分割模型快速试验（需要网络下载权重）

Windows 使用隔离的 Python 环境：

```powershell
.\.venv\Scripts\python.exe -m pip install ultralytics
.\.venv\Scripts\yolo.exe segment predict model=yolo26n-seg.pt source=path/to/image.jpg
```

这一步只验证模型推理工具是否能工作，**预训练 COCO 类别不一定包含用户自己的轴套、L 型支架和三指接触标签**。预训练结果并非最终算法。

### R2：自定义工件数据训练实例分割（必须先有真实数据）

按官方 [YOLO 实例分割标签规范](https://docs.ultralytics.com/datasets/segment) 建数据集，用 CVAT 导出 Polygon 标注后，做小样本训练冒烟：

```powershell
.\.venv\Scripts\yolo.exe segment train model=yolo26n-seg.pt data=datasets/workpieces_v1/data.yaml epochs=5 imgsz=320 batch=4 device=cpu seed=42
```

必须保存日志、模型、Python/PyTorch/Ultralytics 版本、数据划分、错误样本；正式训练再根据 GPU/显存和训练曲线调整。**不得声称本包已经训练完成**。

## 3. 开源方案复现必须记录的 12 件事

1. 仓库作者与官方仓库 URL。
2. 使用的 Commit SHA 或 Release Tag。
3. LICENSE 文件及模型权重、数据集的独立许可。
4. 操作系统、Python、GPU 和驱动版本。
5. 安装环境与锁定依赖。
6. 原仓库提供的最小复现命令。
7. 自己执行的命令与日志路径。
8. 输入数据来源、格式和样本数。
9. 训练/验证/测试的固定分组与随机种子。
10. 输出模型、预测图、测试报告和真实计算指标。
11. 相比官方示例的修改清单与理由。
12. 是否已经接入 H743、是否上过真实机械爪：必须分别记录，不能混写。

## 4. 与三指夹爪相关的复现策略

- **要先复现物体识别，再开发三指抓取规划。** YOLO Mask 不包含接触力、失电保持或摩擦数据。
- 很多抓取研究面向 **parallel-jaw** 两指夹爪或六维姿态，不应将其输出 `(x,y,z,angle,width)` 直接解释成三指夹爪三个关节的控制量。
- **二维平面基线**：固定俯视摄像头、限制物体高度与姿态、相机标定后使用质心/轮廓/旋转矩形给出候选中心。
- **三指规划器**：依据实际指尖结构与开口范围，计算候选接触区域并可视化；缺少机械参数时输出“暂不可执行”。
- **验证闭环**：采集夹爪位置、力/电流、限位、抓取成功与滑移信息；比较几何规则与分割模型提供的抓取候选差异。

## 5. 数据集推荐使用原则

| 来源 | 可借鉴内容 | 注意点 |
|---|---|---|
| 你自己拍摄的工件图像 | 与实际 OV5640、工作台、夹爪最一致 | 需分组拆分、防止连续帧泄漏 |
| [YCB Objects](https://www.ycbbenchmarks.com/object-models/) | 标准物体、实验复现与物体模型 | 类别与机械工件并非完全对应 |
| [GraspNet](https://graspnet.net/) | 抓取评价与三维抓取数据组织 | RGB-D、多视角、抓取器假设需要适配 |
| [MVTec D2S](https://www.mvtec.com/research-teaching/datasets/mvtec-d2s) | 多物体分割与遮挡思路 | 与工业机械零件差异明显，注意非商业用途许可 |

不要因为公开数据集很大就直接混入你自己的工件数据。先使用自采、标签清晰的少量数据跑通全流程，再评估迁移学习或跨域数据的价值。

## 6. 许可证与知识产权

- OpenCV：参考官方 GitHub 仓库和所选版本 LICENSE。
- CVAT：社区版源码核心为 MIT 许可，扩展组件及依赖可能另有许可，按使用组件具体核查。
- Ultralytics：官方说明 AGPL-3.0 与 Enterprise 两种模式。学习、个人研究和愿意遵守 AGPL 条款的开源项目适合评估；闭源产品/商业嵌入式部署需核对条款并可能需要商业许可。
- 开源软件许可证、**预训练模型权重许可证**、**训练数据许可证**要分别核对。
- 第三方仓库中如果没有清楚的 LICENSE，不能仅因 GitHub 上公开便视为完全自由使用。

## 7. 下一阶段该不该寻找更多模型？

不建议现在收集几十个 Grasping repo。最初只固定 **OpenCV、CVAT、Ultralytics** 三条依赖，并留下 GraspNet 为文献/后期算法比较。你真正稀缺的是正确的采集与标注、工件物理尺寸、夹爪结构模型及实验记录，不是开源模型数量。
