# 第一篇｜要解决的到底是什么问题

## 第 1 章 选定课题与范围

本项目选用**方案 B：多形状工业工件自适应抓取**，初期使用方案 A 的规则工件作为简化工况，不改变最终研究主线。目标不是“摄像头看到方块，舵机夹一下”，而是对**多规格、多姿态、不同接触条件**的零件，实现有依据的识别、定位、抓取参数选择和稳定性验证。

### 1.1 一次抓取有多少个环节

```text
物体实际出现在工作台
  ↓ 相机采集（H743+OV5640，初期也可用电脑摄像头）
获得清晰图像
  ↓ 视觉识别：物体在哪里、属于哪类、轮廓是什么
目标检测 / 实例分割
  ↓ 坐标标定：像素不是毫米
工件在工作台上的 (X,Y) 与平面方向 θ
  ↓ 抓取规划：指头能否接触、有没有碰撞、开口多少
候选夹持中心、接近方向、预开口和夹紧策略
  ↓ 机械臂/夹爪控制器（H743 负责安全状态机）
先移动到安全位置 → 对准 → 缓慢闭合 → 判定夹紧
  ↓ 验证实际抓取
是否抓稳、是否滑落、用了多大夹紧力、是否发生异常
```

### 1.2 对五个常见误解的纠正

1. **YOLO 会检测物体，不会自动计算三指夹爪的可靠接触力。** 检测与抓取规划是不同问题。
2. **能识别物体 ≠ 能确定三维空间位置。** 单目相机输出像素；需要标定、固定工作台几何，或后期引入深度信息。
3. **模型训练在电脑/服务器完成。** H743 可以采图、做轻量推理或承担控制，但不是合理的深度学习训练平台。
4. **夹爪能闭合 ≠ 能夹住 5 kg 物体。** 这取决于传动、接触摩擦、反馈、机构、供电和安全设计。
5. **开源仓库能运行 ≠ 与当前机械爪完全匹配。** 很多抓取算法假设两指平行夹爪、深度相机或完整机器人模型，需要适配。

### 1.3 研究对象建议

起步从三类形状各选 3 种实物：圆柱/轴套/短管；方块/矩形块/方形连接件；L 型件/法兰件/不规则支架。最初使用轻质、安全、尺寸可测量的样品；**4–5 kg 负载作为后期台架实验，不要在第一轮视觉测试中使用。**

物体标签可以按两层存储：`shape_group`（几何类型）和 `object_id`（单件身份）。分类标签不必完全照搬商品名称，应该服务于抓取策略。

## 第 2 章 需要掌握哪些知识，不需要掌握哪些

| 层级 | 必须先懂的概念 | 现在不必深入 |
|---|---|---|
| 图像基础 | 像素、分辨率、RGB/BGR、灰度、阈值 | GPU 图形编程 |

| 相机 | 视场、畸变、标定、像素到工作台坐标 | 多相机标定系统 |

## 第 4 章 从像素到毫米：相机标定是必经步骤

固定摄像头、固定工作台、目标主要放在**同一个平面上**时，可以建立简化的像素到工作台映射。

1. 保持摄像头焦距、安装位置、分辨率固定；如果后来移动相机，重新标定。
2. 使用棋盘格等已知尺寸的标定板采集多视角图像，估计内参和镜头畸变。
3. 在工作台平面上布置四个以上已知坐标点；先去畸变，再求平面单应性矩阵 H。
4. 将目标轮廓中心 `(u,v)` 映射至工作台坐标 `(X_mm,Y_mm)`。
5. 再通过工具/机械臂的几何基准把工作台坐标转换成机器人坐标。
6. 使用尺子或定位治具选若干**未参与拟合**的点，测量定位误差；报告均值、最大值和标准差。

单应性适用于目标处于**已标定平面**的近似情形。高出平面的目标，其物理中心、抓取高度和视觉投影会发生变化；如果需要真实三维定位，需增加物体高度估计、深度相机、结构先验或其他测量手段。

### 4.1 你的第一条重要工程指标

**定位误差（mm）** 比仅报模型“识别准确率”更接近真实夹爪的需要。比如识别准确但误差超过最小夹爪开口容差，仍然会夹偏。

## 第 5 章 先做好无训练基线，再训练 AI

建立 OpenCV 基线：固定工作台背景，使用颜色分割或亮度阈值、形态学处理、轮廓面积过滤、轮廓中心和主方向估计，对圆柱、方块、L 型件分别记录是否正确定位。

为什么必须做它：

- 可以检测相机连线、曝光、标定和机械精度，而不需要训练模型。
- 以后 YOLO 分割能否带来性能提升，有了可对照的算法。
- 固定环境下规则工件，传统视觉可能已经够好；不要为了“用了 AI”而无意义增加部署复杂度。

记录失败工况：高反光、低对比度、遮挡、物体粘连、阴影与背景颜色相似等。这些将成为后续训练数据采集计划。

# 第三篇｜第一次训练模型：从工件照片到可复现结果

## 第 6 章 三种常见任务有什么区别

| 任务 | 模型输出 | 你的项目用途 | 建议顺序 |
|---|---|---|---|
| 图像分类 | 这整张图是哪一类 | 不知道具体在哪里 | 理解概念即可 |
| 目标检测 | 各物体类别和矩形框 | 先建立自动选择目标 | 第一次训练 |
| 实例分割 | 每个物体的像素轮廓 | 计算姿态、接触空间和几何尺寸 | **最终重点** |

推荐先拿预训练模型跑通推理，再用自己的工件数据微调；不建议直接从随机参数训练完整目标检测网络。

## 第 7 章 数据集怎么拍、怎么标

### 7.1 第一版数据集

- 第一阶段只选 3 类形状、每类 1–3 个实际物体。先采集 100–300 张用于**打通流程**；分类稳定后再扩充至每种实物约 150–300 张，这是起始规模，不是模型效果保证。
- 每一张图片登记：`session_id`、`object_id`、相机、分辨率、工作台、背景、光照、距离、高度、是否遮挡、是否成功抓取（如有）。
- 拍摄不同角度、位置、光照、颜色、部分遮挡和合理背景变化；避免几百张几乎相同的视频相邻帧。
- **原始文件只保存一次，不对原图执行覆盖式增强。** 增强只在训练阶段或新数据版本生成。

### 7.2 标注工具

推荐 **CVAT**。初次可使用其在线试用或按文档部署社区版；支持框、Polygon 和辅助标注。数据含专有结构或敏感环境时优先本地部署/核对云端隐私与授权。

第一阶段标注类别 `cylinder`、`block`、`irregular` 的 Bounding Box。第二阶段改标 **Polygon/实例分割**。每个物体一组独立实例轮廓；不能将同类的两个靠近零件标为同一个区域。

最重要的标注规范：

- 标注的是**可见物体真实边界**，不要将阴影纳入工件。
- 遮挡后的不可见区域如何处理，要在整个数据集中保持一致。
- 部分出框、反光、模糊、遮挡图像设质量标签，不能悄悄删除所有困难样本。
- `names` 类别顺序不可在一次实验中随意改变，否则 label ID 将错配。

### 7.3 分割数据集格式示例

```text
workpieces_v1/
├── data.yaml
├── images/
│   ├── train/
│   ├── val/
│   └── test/
└── labels/
    ├── train/
    ├── val/
    └── test/
```

`data.yaml` 示例：

```yaml
path: D:/VisionGrasp_Study/datasets/workpieces_v1
train: images/train
val: images/val
test: images/test
names:
  0: cylinder
  1: block
  2: irregular
```

实例分割 `.txt` 中每一行由 `class_id x1 y1 x2 y2 ...` 组成，Polygon 顶点坐标按图宽高归一化到 `[0,1]`；检测任务的 `class x_center y_center width height` 不能直接伪装成分割标签。以 Ultralytics 官方数据格式为准。

### 7.4 训练/验证/测试分组

可以按约 70% / 15% / 15% 起步，但要按**拍摄时段、场景和物体身份**分组，而不是将同一连续视频的相邻帧随机分到训练和测试中。测试集只用于最后评估，不反复根据测试结果调参。可另外做一个“未见实物/未见光照”外推测试集合，检验泛化能力。

## 第 8 章 YOLO 实例分割第一次训练

2026 年 Ultralytics 官方文档提供 YOLO26 实例分割训练流程。为了可复现，先固定软件版本、模型名称、数据集版本和随机种子；本书仅提供启动命令，不声称模型已实际训练。旧教程中的 YOLOv8 与新版本接口可能仍可用，但不要混合未核实的脚本参数。

### 8.1 环境

```powershell
.\.venv\Scripts\python.exe -m pip install ultralytics
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

如果有 NVIDIA GPU，用 PyTorch 官方安装向导选择与你驱动、Python 和 CUDA 条件匹配的安装命令；**先记录显卡型号和显存**。没有 GPU 也能做小规模 CPU 冒烟测试，但完整训练会慢很多。

### 8.2 先验证环境能推理

```powershell
.\.venv\Scripts\yolo.exe segment predict model=yolo26n-seg.pt source=path/to/test_image.jpg
```

上面的命令只展示通用推理能力，并不能保证预训练模型识别你自制的工业工件类别。下一步才进行数据集微调。

### 8.3 先跑 5 epoch 冒烟训练

```powershell
.\.venv\Scripts\yolo.exe segment train model=yolo26n-seg.pt data=datasets/workpieces_v1/data.yaml epochs=5 imgsz=320 batch=4 device=cpu seed=42
```

此阶段验收的是**环境、标签、梯度、日志、模型保存全流程能走通**，而不是识别率达标。此命令可能会下载预训练权重，首次运行需要网络。正式训练时在已记录 GPU/驱动的前提下调整 `device`、`imgsz`、`batch`、`epochs`，保留对比组和固定测试集。

### 8.4 正式实验建议（不要一次改变多个变量）

- E0：传统 OpenCV，不训练，作为经典基线。
- E1：YOLO detection，小模型，固定数据集。
- E2：YOLO segmentation，小模型，固定数据集。
- E3：按少量反光、遮挡、复杂背景补充数据，再训练分割模型。
- E4：保持同一识别模型，比较不同抓取规划规则。

必须记录软件与数据版本、模型预训练权重、随机种子、图像尺寸、轮次、批量、训练设备、学习率（或默认参数）、评估脚本和实际训练时间。

### 8.5 看哪些指标

识别层：每类别 Precision、Recall、mAP@0.5、mAP@0.5:0.95；分割层：Mask IoU / Mask mAP；定位层：未见样本的工作台 mm 误差；执行层：抓取成功率、接触前误差、滑移、循环时间。

正确的研究结论不是单纯“准确率 95%”，而应该包含测试集定义、样本数、失败分布、与 OpenCV 基线相比的提升，以及对抓取成功率的真实影响。

# 第四篇｜让 AI 识别真正变成三指抓取

## 第 9 章 识别结果如何转换成抓取参数

一个典型接口如下（示例，不是已实现的机器人协议）：

```json
{
  "object_id": "sample_023",
  "class": "block",
  "score": 0.94,
  "camera_frame": "cam_top",
  "center_px": [312.4, 208.6],
  "center_work_mm": [125.1, 84.6],
  "orientation_deg": 32.0,
  "estimated_width_mm": 48.0,
  "grasp_candidate_id": "c01",
  "grasp_valid": false,
  "invalid_reason": "unverified_clearance"
}
```

为什么初始例子把 `grasp_valid` 设为 `false`？因为一个正确的视觉位置，还需要完成**工作空间、接触点、夹爪开口和安全检查**，才能转为真正的运动命令。`score` 是示例字段，不是当前模型的真实输出。

## 第 10 章 三指夹爪不是两指夹爪：如何选策略

建议至少建立三类简单抓取策略，并与夹爪实际结构匹配：

1. **圆柱类**：优先从顶视轮廓估计中心和直径，三指尽可能均匀包围，检查最小/最大开口与指尖接触半径。
2. **矩形类**：估计旋转矩形和长短边；某些三指构型可采用“两侧支撑+对向一指”的接触方式，不能强制按圆柱三等分。
3. **L 型与异形类**：从轮廓中提出可接触区域，避开凹槽、尖角、孔洞、薄壁和干涉区域；在缺少力学验证时，拒绝高风险抓取。

“自适应”建议区分两个层次：**结构自适应**（欠驱动/连杆能够适应外形）与**算法自适应**（根据目标几何选择开口、姿态、接近方向和夹紧策略）。它们可分别进行消融实验。

### 10.1 初版规则抓取规划器

输入：类别、分割轮廓、工作台坐标、工件尺寸估计、夹爪最大/最小开口、物理安全边界、夹爪自身模型。输出：`reject_reason` 或可视化的候选抓取方案。

步骤：

1. 实例分割获得工件 Mask。
2. 过滤边界被裁切、置信度过低或严重遮挡物体。
3. 计算目标质心、旋转矩形、凸包、凹凸区域和主要方向。
4. 依据形状选择候选接触布局，估计各指张开距离。
5. 检查工作空间、碰撞、机械行程和接近通道。
6. 生成**只读可视化**候选点，先由人确认与工件位置对应。
7. 只有机械臂/夹爪具备闭环反馈与安全状态，才允许发送执行命令。

### 10.2 抓取质量不能从 Mask 单独得出

实际抓取还依赖质量、重心、摩擦、材料、手指刚度、真实接触位置与夹紧力。在没有力传感器和可靠标定前，“稳定度评分”最多是几何启发式，**不能写成已具备力闭环控制**。

## 第 11 章 真实的标定链路

你最终可能有这些坐标系：

```text
相机图像坐标 {I}  ← 去畸变/标定 → 工作台坐标 {T}
机器人基座坐标 {B} ← 标定/固定装配 → 工作台坐标 {T}
末端执行器坐标 {E} ← 手眼/工具偏置 → 夹爪抓取中心 {G}
```

固定俯视相机 + 固定平面时，先实现二维 `(X,Y,θ)` 和固定安全高度，再升级到三维位姿。眼在手（eye-in-hand）与眼在外（eye-to-hand）标定方法不同，不能把像素中心直接视为夹爪 TCP 位置。

## 第 12 章 如何证明夹得稳

将视觉性能和机械性能分别测量：

| 变量 | 测量方式 | 报告 |
|---|---|---|
| 识别结果 | 固定保留测试集 | 每类混淆矩阵 / Mask mAP |
| 工作台坐标误差 | 标定治具、量具 | 平均/最大误差 mm |
| 实际预对准误差 | 标尺/视频/定位机构 | mm/角度 |
| 轻载抓取成功率 | 重复抓取并放置 | 成功/总尝试，附失败原因 |
| 夹紧力 | 经标定的力传感器 | N；不以电机电流直接替代 |
| 滑移/掉落 | 安全台架、限位保护 | 事件率、保持时间 |
| 4–5 kg 能力 | 独立静态工况、渐进载荷 | 只在机械、电源、保护就绪后测试 |

建议每个实验的样本数、物体形状、质量和姿态预先写明，防止训练后只展示最成功的一两次。

# 第五篇｜与 STM32H743 + OV5640 接起来

## 第 13 章 你的硬件与视觉算法的关系

当前的硬件基线：H743ZIT6、LXB743ZI-P1、OV5640 的 DVP/DCMI、1.54 英寸 SPI6 显示屏、25 MHz HSE、IAR EWARM 9.40.1、CubeMX 6.17.0。主控板具有片内多区域 RAM、W25Q64 非易失性 Flash，未在现有原理图中确认外部 SDRAM。

因此按以下方式设计：

- **PC**：保存训练数据、标注、训练模型、执行较复杂推理、评估结果。
- **H743**：DCMI 单帧采集、基本缓冲管理、SPI6 状态屏、通信、夹爪执行器状态机与故障处理。
- **ESP32（可选）**：网络/网页控制，不必在第一阶段加入。
- **外部视觉计算模块（有必要才加）**：后期模型超过 H743 RAM、Flash 或实时性要求时再考虑。

第一阶段可以先用 PC 摄像头验证全算法：这不是改变最终硬件，而是让算法先与摄像头驱动问题解耦。随后 H743 通过 SD 卡、USB、以太网或其他已验证通道输出采集图像到电脑；若使用 UART，不能假定全分辨率原始图像能达到实时传输要求。

## 第 14 章 端到端联调的七个里程碑

1. **M0**：PC 本地 OpenCV 演示 + 测试通过，不接运动硬件。
2. **M1**：PC 相机采集真实工件图片，进行标定，得到像素→mm 实测误差。
3. **M2**：训练完成目标检测/实例分割基线，固化测试集与结果。
4. **M3**：H743 的 OV5640 完成低分辨率 DCMI 单帧采集；图像能导出供 PC 校验。
5. **M4**：PC 输出结构化目标和抓取候选，H743 只接收并打印，不驱动电机。
6. **M5**：单独台架轻载夹爪有位置、限位、断能和安全状态，通过人工许可执行低速动作。
7. **M6**：完成视觉定位 → 安全抓取 → 分拣 → 记录成功率的实验；然后评估是否真的需要 H743 本地推理。

每个里程碑先写明“输入、输出、可视证据、失败退出条件”，通过后再进入下一阶段。不能把通过 PC 推理写成“H743 已运行 AI 模型”。

## 第 15 章 H743 上什么时候运行神经网络？

**不是一开始。** 等你有稳定的数据集、训练模型和抓取评价以后，再进行离线量化、模型导出、嵌入式兼容性检查、RAM/Flash/延迟测量。H743 的 1 MB 片内 RAM 分在多个区域，DCMI DMA 与 D-Cache 一致性是难点；`W25Q64` 是 Flash，不是 RAM。

需要比较三个方案：

| 方案 | 算法 | 优势 | 代价 |
|---|---|---|---|
| PC 推理 + H743 控制 | 原始 YOLO Seg / OpenCV | 快速教学、可调试、模型灵活 | 依赖 PC |
| H743 本地 OpenCV 简化算法 | 阈值/轮廓/几何 | MCU 延迟与资源可控 | 光照与复杂背景敏感 |
| H743 本地小模型 / 外挂 AI 板 | 量化推理或协处理器 | 有利于独立系统 | 内存/部署/功耗与维护复杂 |

也不要把“Tiny 模型能加载”当作“实时稳定”；还需包含图像预处理、推理、后处理、系统中断、图像缓存和控制周期总时延。

# 第六篇｜用 Codex、DeepSeek、豆包辅助研发

## 第 16 章 AI 能帮你做什么、不能替你保证什么

| 任务 | Codex（本地项目工作流） | DeepSeek/豆包对话助手 | 人需要确认 |
|---|---|---|---|
| 搜寻开源仓库与文档 | 具备联网或连接工具时可做 | 具备联网检索时可做 | 来源、许可证、日期与可靠性 |
| 学习术语、讲算法 | 可以 | 可以 | 是否真正理解输入输出 |
| 搭建 Python 隔离环境 | 可生成并在获准环境执行命令 | 可给指令，具备执行功能时才可执行 | 环境版本与权限 |
| 编写训练和评估脚本 | 可以 | 可以生成脚本 | 真实运行、日志和失败样本 |
| 整理/检查标注 | 可以批量验证格式与统计 | 可以解释标注规则 | 轮廓是否正确 |
| 训练模型 | 仅在有实际机器、数据、权限、算力时发起 | 同样取决于实际可执行环境 | GPU、耗时、费用、训练日志、真实指标 |
| H743 联调 | 能辅助改 C/CMake/IAR 配置 | 能分析问题 | 实物接线、供电、调试结果 |
| 实体抓取验证 | 可写协议、仿真和检查表 | 可辅助设计实验 | **人工批准、机械安全、电气安全** |

你本地的 Codex 若已在 VS Code 内，并对本地工作目录获得权限，就非常适合用来**执行具有明确验收标准的分阶段任务**。普通聊天窗口中的 AI 不会因为输入“请训练”就自动访问你的本地 GPU 或文件；具体能力取决于所用产品的执行工具和授权。

## 第 17 章 AI 辅助开发的标准循环

```text
人定义目标与验收
    ↓
AI 搜索官方/开源文档 → 记录仓库 commit、依赖版本、许可证
    ↓
先复现原作者最小样例 → 保存标准输出/运行日志
    ↓
换成你的数据集 → 验证标注、类别、拆分与图像尺寸
    ↓
运行短训练/测试 → 记录真实 mAP、延迟、显存等
    ↓
分析错误样本 → 一次只做一类改动
    ↓
与固定基线对比 → 保留成功/失败证据
    ↓
经人工审阅后合并，进入下个阶段
```

### 17.1 对 Codex 的必要约束

- 默认仅允许新建和修改 `Vision_AI/` 或独立研究仓库，不触碰旧版 `H743_BringUp`、历史 `servo`、STM32Cube 官方 SDK。
- `datasets/raw`、标注原件、锁定测试集只读；清理缓存时不递归删除原数据。
- **没有真实运行不得写“训练成功”。** 每个实验必须报告命令、环境、数据量、训练耗时、日志路径、输出文件和指标。
- 不得通过修改测试集标签、删除困难样本、仅汇报最佳样例来伪造效果。
- 所有与夹爪、电机有关的命令默认 Dry Run，只生成候选动作；实物上电、使能与负载抓取由人完成。
- 每次发现设备无法运行，先报告缺少的板卡、协议、固件条件，不编造“已验证的引脚和机械参数”。

随包的 `04_Codex_分阶段执行与验收指令.md` 可以直接交给本地 Codex，先执行只读环境审计，再分批建工具与实验。

# 第七篇｜12 周学习与交付计划

这是一套按周安排的**建议课程**，并不是时间保证。你可以依据课业、机械设计进度与是否有 GPU 自由调整。

| 周次 | 学习重点 | 实际动手 | 通过标准 |
|---|---|---|---|
| 1 | 像素、颜色、图像读取 | 跑通随包模拟三形状演示 | 2 个单元测试通过，能解释 JSON |
| 2 | 二值化、轮廓、几何 | 换用真实物体照片 | 能指出过曝、阴影导致的失败 |
| 3 | 相机基础与标定 | 棋盘格、工作台坐标 | 给出未见点定位误差表 |
| 4 | 数据采集与标注 | 拍 100–300 张、标注若干类 | 标签/图像检查通过 |
| 5 | 数据格式与模型运行 | 跑通 YOLO 预训练推理、训练冒烟 | 训练完成且日志可读（不是准确率达标） |
| 6 | 首个检测模型 | 使用固定拆分训练检测模型 | 交付每类指标与失败样本 |
| 7 | 实例分割 | 标注 Polygon、微调 Seg 模型 | Mask 指标可复现 |
| 8 | 视觉定位算法 | Mask → 平面中心/方向/尺寸 | 误差在独立样本上可测 |
| 9 | 抓取规划 | 三类工件策略 + 仅可视化 | 拒绝不可达/越界目标 |
| 10 | H743 图像通路 | OV5640 单帧导出/对比 | 能保存并检查一张真实图像 |
| 11 | 控制协议与轻载台架 | H743 接收候选，先 Dry Run | 超时/错误帧/安全状态通过 |
| 12 | 综合展示与论文实验 | 分拣演示及统计 | 形成可复现的实验包和失败分析 |

若阶段 10 的 H743 摄像头驱动尚未完成，可继续用电脑摄像头进行视觉实验，不必阻止前面的算法学习。

## 论文/毕业设计可以研究什么

建议三个可以实测的变量维度：

- **视觉方法比较**：OpenCV 轮廓 vs YOLO 检测 vs YOLO 实例分割，比较定位误差、识别率、运行延迟。
- **抓取策略比较**：固定中心抓取 vs 按轮廓与形状选择接触区域；比较成功率、对准误差和滑移。
- **机构/负载比较**：不同指尖材料、夹紧力/机构参数和目标形状；比较保持能力与失败模式。

最后给出分形状、分尺寸、分姿态、分重量的分组实验。**不要只报告一个总体准确率**，也不要把重载抓取能力与视觉识别准确率混成同一个指标。

# 附录 A｜常见故障与处置

| 现象 | 优先检查 | 不建议做法 |
|---|---|---|
| Python 运行不了 | 解释器、venv、依赖版本 | 覆盖系统 Python/其他项目环境 |
| 图像识别错 | 曝光、模糊、类别和数据拆分 | 一上来换最大模型 |
| 分割标签报错 | Polygon 坐标是否归一、类 ID、缺失标签 | 随便改标签填充 |
| GPU 不工作 | `torch.cuda.is_available()`、驱动和 PyTorch 版本 | 盲目安装不同版本 CUDA |
| 模型 mAP 高但抓取差 | 相机标定、平面假设、开口和机构控制 | 把识别置信度当抓取稳定度 |
| H743 图像乱码 | OV5640 格式、DMA、缓存、帧边界 | 认为模型训练错误 |
| 抓取时 MCU 重启 | 动力与逻辑电源、干扰和过流 | 继续提高 PWM 占空比 |
| Codex 说训练完成却无证据 | 运行命令、日志、权重、数据版本 | 直接写进论文 |

# 附录 B｜核心术语速查

- **Bounding Box**：目标框，包含但不精确描述物体边缘。
- **Instance Segmentation**：实例分割，同一类的不同物体可分别给出 Mask。
- **Mask**：像素级工件区域。
- **Homography**：同一平面两种二维坐标之间的投影映射。
- **IoU**：预测区域与真实区域交并比。
- **mAP**：检测或分割精度的多阈值汇总指标，需注明计算条件。
- **Precision / Recall**：预测为目标的正确比例 / 真实目标找回比例。
- **Epoch / Batch**：训练遍历一轮数据 / 一次迭代使用的样本量。
- **Overfitting**：训练集表现好，未见数据效果差。
- **Transfer Learning**：使用已有预训练权重在自有数据上微调。
- **Calibration**：测定相机内参与相机/工作台或机器人关系。
- **TCP**：机械末端执行器参考点，并不自动等同于视觉中心。
