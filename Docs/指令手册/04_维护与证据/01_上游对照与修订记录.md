## 发现和处理的偏差

| 事项 | 核对结果 | 本轮处理 |
|---|---|---|
| 原有二进制指令与`@`并存 | 原协议没有被`@`取代 | 建统一入口和按任务映射表，没有虚构文本别名 |
| F5支持范围 | 上游Build/IsFrame仅Cmd00–03；当前H743增加04/05 | 单独标记两路PWM虚拟键扩展 |
| F5 A0/B0的0/1 | 进入虚拟电平与手势；2/3等走兼容动作 | 写明按下/松开时序与直接动作区别 |
| 当前参数列表 | 0–20共21项 | 旧表21–25参数不列入当前支持；保存边界单独说明 |
| 旧表PWM引脚 | PA6/PB1为F103旧映射 | H743当前PD12/PD13；旧表加历史提示，不当现用接线 |
| 位置模式帧尾 | `FF FF 01 04 03 21 00 D7`校验不正确 | 正确文档示例尾为D6，离线核验验证；固件F1内置示例字符串暂未改动 |
| `@help`不完整 | 漏列pwm2/pwm angle；clock帮助值少于驱动接受集合 | 完整表按源码分支列出，不修改help行为 |
| USB CDC的能力 | `@`执行，其他字节回显 | 明确不支持USB二进制控制，避免用户把回显当ACK |
| 离线命令栈 | 在线且ID匹配才启动；接收FIFO先存在 | 明确队列/启动条件，不声称离线命令已处理或一定丢弃 |
| 旧文件头注释 | VOFA写USART3、Bluetooth写USART1 | 按实际角色HOST→USART1、BT→USART3记录；不改固件源码 |
| F5尾字节 | Build写00；IsFrame不强制校验00 | 文档区分规范发送与实际宽松接受 |
| 参数文本回复 | 列表只打印中文名称与当前值 | 不沿用旧表“同时输出默认/范围”的保证 |

旧表正文作为历史保留并加入口提示；上述固件层偏差只登记，不借文档整理改变运行行为。生产固件相关文件哈希核验应保持与本轮开始时一致。

## 后续新增指令的记录规则

每条记录应包含：稳定标识、所属层、入口/波特率、完整语法、参数类型/单位/范围、状态前提、返回及成功判据、是否动作/写存储、是否掉电保留、例子与源码位置。不要只在`@help`字符串里新增一段名字。

文本命令新增/删除后同步[目录JSON](文本指令目录.json)、完整表和离线核验；F命令新增需更新宏、Build/Decode/分发、App控件配置和二进制示例。已有编号不悄悄换含义；需要兼容时在对照页说明。

未来若真正增加同义`@`业务命令，应在执行层调用同一业务API，而非复制一套动作逻辑；这属于后续固件研发，本轮没有实现。屏幕交互规则等待用户后续说明，不在这里预设菜单协议。


## 离线工具使用

在H743目录运行，下面命令只打印HEX，不打开串口：

```powershell
python Tools/command_frame.py ping 0
python Tools/command_frame.py read 0 0x38 2
python Tools/command_frame.py f5 0 90
python Tools/command_frame.py local F2 02 04 84 03
python Tools/verify_command_manual.py
python Tools/validate_learning_library.py
```

`local`的指令码与每个参数按HEX解析；`ping/read/f5`的ID/数量/Cmd按十进制或0x前缀解析，f5的值为十进制float。工具只保证此处格式和编码，不判断目标机构行程、当前模式或设备是否允许动作。

核验将检查32个文本分支与目录一致、本文42组完整字节示例（41组有效格式、1组历史错误反例）的长度/校验或F5浮点布局，以及当前15个关键源文件快照。示例是离线算术验证，未在板上逐条执行。新增示例后同步目录，再运行核验，避免文档写了一个帧但工具只检查旧集合。
