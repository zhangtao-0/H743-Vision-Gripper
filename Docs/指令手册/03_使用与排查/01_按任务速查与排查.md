# 按任务速查：从连接到控制

## 先做不会启动执行器的查询

1. 连接HOST USART1/115200或已枚举USB CDC，以文本发送`@help`、`@status`。确认有SYS/CAM/STS/MOTOR信息，而不是只有输入回显。
2. 摄像头问题可依次发送`@camera off`、`@lcd test`，观察显示，再`@camera on`和`@status`看帧与错误。正常预览恢复后不要继续把色块覆盖当作屏幕失效。
3. STS仍未在线时用`@servo probe 0 1000000`和状态记录排查。accepted只表示请求被接受；rawRx=0应先查供电、电气链路与波特率。
4. 原命令栈确认已启动后，再经HOST或蓝牙HEX发送F4查询、F2参数列表、F0单次反馈。USB CDC不能执行这些二进制命令。

这不是一份自动运行脚本；每一步依据观察决定下一步。不要把后续动作/擦除示例加到“上电自动发送”列表里。

## 一个目标该用哪个入口

| 目标 | 选用 | 不等价的命令 |
|---|---|---|
| 查看整个H743外设状态 | `@status` | F0只看claw反馈 |
| 只读更换MCU侧探测ID/速率 | `@servo probe ID BAUD` | 官方写EEPROM真的会改变设备 |
| 让夹爪按目标角度动作 | F5 Cmd00 | `@pwm angle`针对PWM舵机 |
| 配置夹爪张开速度 | F2 ID04 | `@motor rpm`针对MG310 |
| 调MG310闭环速度 | `@motor rpm N`并按条件enable | STS速度寄存器单位/对象不同 |
| 请求停止STS动作 | F5 Cmd01值3，检查反馈/结果 | 不自动停止MG310/PWM；不是卸力 |
| MG310停止 | `@motor stop` | 不停止STS，且stop不清fault |
| 关闭两路PWM输出 | `@pwm off` | 不等于舵机主动保持当前位置 |
| STS扭矩卸力 | 官方写0x28=0（受审查） | 与保持式停止不同，负载可能松脱 |
| 关闭CSV | `@stream off` | 不能关闭F0或P3日志 |
| 关闭claw周期反馈 | F0 action0 | 不能关闭全部系统输出 |
| 恢复运行参数 | F2 action4 | 不等于清除机械极限 |
| 放弃本轮标定 | F4 action4 | F4 action5是清除已存极限 |

## MG310控制顺序

无H桥时只查status/输入与计数，profile0禁止enable是预期行为。配备并验证驱动、供电和反馈后：先stop；需改CPR/PID时在停止状态设置并检查布尔返回；设置低目标RPM，再enable，观测rpm10、pwm、fault和实际方向；停止后再做下一试验。

reverse仅改变请求方向，不启动设备；换向先滑行等低速。clear会停止并清fault，随后仍需重新设置目标/使能；不能用连续clear掩盖反馈接反或堵转。电机命令的CPR输入单位与status的cpr1000不同，详见[完整表](../01_文本控制台/01_完整AT指令表.md)。

## 常见“没反应”原因

- 把HEX字符当文本发，或把`@status`放进HEX模式；先确认实际发送字节与行尾。
- USB只回显二进制，原业务处理并未运行；换到HOST或蓝牙正确入口。
- 原STS栈尚未在线启动；不是所有F0查询都在任何状态可执行。不要在离线FIFO积压动作。
- 蓝牙UART是9600，STS总线起始1Mbps，HOST115200；不是一个波特率通用。
- `@`整行未换行、输入字符间隔过长、邮箱忙，或大小写错误；查看cmdDrop。
- 动作被范围/反馈/驱动profile/运行互锁拒绝，或当前编译目标关闭了设备。阅读真实返回，不能将1/0统一解释。
- 虚拟按钮缺少松开帧；检查发送工具是否同时配置按下/松开以及断线后的恢复逻辑。
- 写帧只报告发送成功、未等待ACK；检查反馈而非仅看日志文字。

## 回执怎样解释

`motor target=1`是接受请求的布尔值；`RTC set=0`是HAL_OK。`STS valid`说明解析到回应，不等于机械动作到位。F4 ACK的status=0表示本次处理成功；仍需核实setting/valid/range字段。某些文本分支本来没有确认行，使用状态查询补充判断。

屏幕翻页、确认/取消与快捷观测已在后续[屏幕交互手册](../../屏幕交互/README.md)定义；没有占用现有F5编号，菜单直接调用业务API。
