# 接线、打开电脑预览、保存训练原图

## 两条数据通道

| 用途 | 接线与软件 |
|---|---|
| 电脑图像 | 开发板已经实现USB Device CDC的数据口→电脑数据线；运行viewer独占其COM |
| VOFA和原舵机控制 | USB-TTL TX→PA10/RX，RX→PA9/TX，共地；115200、8N1；继续使用原@或HEX协议 |
| 摄像头 | 保留当前已验证的FD5640接线；本版不重新分配其引脚 |

不要将ST-Link调试口或只充电的USB口认成摄像头COM。不要让VOFA和viewer同时打开同一个COM。板上存在多个供电入口时，继续遵循[供电档案](../硬件档案/README.md)，不要为传图任意并接不同电源；USB传图不改变舵机或电机的供电要求。

本版固件尚未烧录。旧固件不认识video命令；应先按项目原有下载流程下载本版对应传感器配置，保留复原备份。本轮没有擅自操作连接中的设备。

## 已准备的电脑程序

在H743目录使用PowerShell：

```powershell
# 列出所有串口，结合拔插数据线判断哪个是USB CDC
& .\Host\vision_gripper\.venv\Scripts\python.exe .\Host\vision_gripper\viewer.py --list-ports
# COM号只是示例，替换成真实USB CDC端口
.\Host\vision_gripper\启动预览.ps1 -Port COM12
```

当前隔离环境已安装numpy、Pillow、pyserial、opencv-python。程序启动后通过USB依次发出video fps、camera live、video on；默认帧率上限2，实际帧率取决于采集、LCD、USB端点及主循环。它是低分辨率预览链路，不承诺30fps或给定延迟。

看到画面后移动黑包或箱体，确认电脑画面变化；按S或“Save raw image”保存。原始PNG与JSON写入`Host/vision_gripper/data/raw/日期_随机场次/`，不会把屏幕旋转后的图像或绿色标记写入训练原图。换灯光/背景/物体/拍摄场次请重新启动程序，形成独立session。

关闭窗口会尽力发送video off。突然拔线、程序崩溃、端点不读时，固件有发送超时释放与建议过期规则；不是所有退出情况都能收到最后一条串口命令。

## 排查顺序

1. 程序提示打不开端口：确认COM和占用软件；不要误关USART1上的VOFA。
2. 没图：在USART1发送`@video status`和`@status`，确认新版固件、USB=1、CAM ready/enabled；必要时先恢复camera live。
3. CRC错误增长：记录计数、线缆、程序版本与USB丢弃计数，排除旧固件/错误串口/传输中截断；不要跳过CRC显示坏帧。
4. 摄像头关闭或冻结：video on只开启传输，不代替camera live；冻结只会得到同一完成帧，不会伪造实时帧。
5. 要暂停图像用`@video off`。`@quiet`保持其原有关闭周期文字/CSV的含义，不自动关闭主动启用的视频。

图像之外的文本仅在完整图像帧之间输出，USB回复可能等待一帧完成。USART1没有图像负载，原控制入口保持。关闭视频后USB恢复原文本使用方式。
