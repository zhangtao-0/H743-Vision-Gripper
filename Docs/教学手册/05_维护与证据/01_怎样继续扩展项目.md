# 给项目增加一个设备，应该按什么顺序做

## 从需求到最小链路

先写目标与可观测结果：需要什么输入、什么输出、真实反馈是什么。再确认器件完整型号、供电、电气接口与原理图引出，列出资源冲突和保留项。

先做底层最小实验，例如读ID或固定波形；再写设备驱动；再接入有边界的service；最后由app或console映射业务。不要先给App塞一百行HAL调用，再想怎样迁移。

## 配置和代码放哪里

通用原理进入 [知识体系库](../../../../../../20_Knowledge-研发知识库/09_系统学习手册/README.md)，本项目接线/采用参数进入工程Docs，器件原始资料留在资料库/官方参考区，源码保持在project。新增设备不复制一套HAL；按需要增加当前版本的源文件和开关。

硬件变化集中在板型/platform，设备协议集中driver；纯算法尽量不依赖HAL。IRQ与回调接入既有分发，检查同名强定义和共享向量。

## 怎样维护两类库

知识手册讲可迁移方法，更新时写明适用芯片/HAL边界；项目手册讲具体实现，改代码后刷新函数定位和资源表。只维护一个权威引脚CSV，其他文件链接过去。

按“原理推导、当前采用、实测证据、待验证”区分内容。新增项目可以使用 [项目卡片](../../../../../00_项目库导览/02_新项目卡片模板.md)登记，不应复制H743固件并改个名字就称为新成果。

## 变更收尾

保存必要备份，记录原因与替代配置，检查链接、API引用、工程注册、map及对应层测试。若尚缺H桥或器件资料，完成可独立完成的代码/文档，并明确剩余硬件验收，不把缺项藏在“编译通过”后面。

本轮没有修改SDK、外设配置或应用代码。维护脚本只检查教学资料和基线差异，详见 [资料验证脚本](../../../Tools/validate_learning_library.py)。
