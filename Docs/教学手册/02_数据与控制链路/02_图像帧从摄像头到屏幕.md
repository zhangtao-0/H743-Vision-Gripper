# 一帧图像的生成、搬运、接受与显示

## 第一步：控制摄像头

`DCMI_OV5640_Init`准备SCCB、DCMI、DMA、复位、ID与寄存器表，建立RGB565和尺寸。当前配置传感器400×300，再裁成240×240。

`BoardCamera_Init`还检查SCCB错误计数和关键寄存器读回，避免把ACK失败、格式错误仍当作ready。期望format=6F01、默认PCLK配置读回2204。

## 第二步：启动快照

[BoardCamera_Task](../../../project/App/platform/board_camera.c)在等待状态选择DMA_NORMAL，用 `HAL_DCMI_Start_DMA` 采一帧到 `.camera_dma`。数组为240×240个uint16，115200字节，API长度28800个32位word。

此时CPU可以执行其他任务，像素由外部PCLK经DCMI/DMA抵达AXI SRAM。SCCB仍只是寄存器控制链，不能把它当成传图链。

## 第三步：决定能否显示

只有帧结束标记、DMA READY、无错误、NDTR=0同时满足才接受。否则在错误或超时时停止并保存诊断。接受后停止采集、发布显示状态；不是在DMA还写入同一缓冲时随意读整帧。

## 第四步：分条给屏幕

每次Task调用发送4行，由 `LCD_CopyBuffer` 设置显示窗口、切16位SPI数据宽度并发送像素，最后恢复8位以便命令使用。发完整帧后再等待下一次采集。

LCD状态行只在没有正在分条显示时写，避免同一主循环阶段与图像带交错。新一帧仍可能覆盖状态区域，`@camera off`可用于稳定观察状态。

## 怎样重现诊断思路

先 `@camera off` 再 `@lcd test`：稳定色块说明屏幕基本链路可用；再对比MCU帧缓冲是否已经异常。原故障条纹也出现在缓冲还原图，促使排查采集而非只调整屏幕。

旧版本4分频现场曾329帧、0超时；当前电机扩展固件不同，教学文档不能据此称新版本全部实测通过。阅读 [完整故障记录](../../故障排查/20261021_花屏与舵机离线/排查与修改记录.md)，保留8分频失败等证据。

练习：写出frames增加、timeout增加、remaining=28800、remaining小于28800各自可能意味着什么；单个数值不足以唯一确定故障原因。
