# 从目录找到职责，而不是逐个文件盲读

## 工程地图

```text
project/
  Core/        启动后入口、系统时钟、MSP、中断转发
  Drivers/     当前芯片CMSIS与HAL，不是业务代码
  App/
    config/    功能开关、PID/设备参数
    platform/  HAL适配、板型映射、存储与DMA约束
    bsp/       按键、蓝牙等已有板级服务
    drivers/   STS/PWM舵机等设备实现
    vendor/    从厂商示例适配的屏幕/摄像头/存储驱动
    modules/   P3、命令整合、纯电机算法与服务
    protocol/  HOST协议和发送队列
    app_main.c 应用组织
  Middlewares/ FatFs、USB库
  USB_DEVICE/  USB应用接口与PCD对接
  EWARM/       IAR工程、启动文件、链接配置、构建输出
```

命名是历史形成的，不保证每个目录都严格遵循同一种分层。阅读时更应看依赖方向，例如 `board_camera` 同时承担采集服务，不是只有一组引脚函数。

## 三个最有用的分界

- 原理与硬件：`motor_control`不含HAL，`board_motor`负责TIM/GPIO。
- 字节与协议：`board_uart`不懂STS包，`feetech_sts_bus`不应决定PA2。
- 能力与业务：屏幕驱动提供画图，应用决定显示STS或电机状态。

统一入口 [platform_hal.h](../../../project/App/platform/platform_hal.h)选择SDK头文件；[board_resources.c](../../../project/App/platform/board_resources.c)把UART角色映射到句柄；板型下的board_profile汇总六组GPIO/外设/时钟配置，旧board_devices只保留兼容转发。它们降低迁移成本，但不自动改写另一MCU的Flash/DMA机制。

## 推荐阅读顺序

先main与app_main，知道谁调用谁；再看配置与资源，知道哪些引脚被占；选择UART或LED一条最短链；然后摄像头帧链；最后看控制器、持久化和并发。

不要从字体数组或摄像头几百条寄存器表第一页开始通读。先找Init/Task/IRQ与状态结构，再按需要回到具体表项。
