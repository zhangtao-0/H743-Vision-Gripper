# 构建、测试与固件版本：如何判断“验证完成”

## 已有脚本分别测什么

| 工具 | 验证范围 |
|---|---|
| run_p2_host_tests.py | UART角色/状态、LED极性、按键与HOST模型 |
| run_p3_host_tests.py | STS帧、只读探测、反馈与回退 |
| run_camera_regression.py | 真实相机状态机的完成/错误帧模型 |
| run_integration_host_tests.py | 控制台路由、Flash故障模型、原PWM控制 |
| run_motor_tests.py | 实际纯C PID/EC11/服务与模拟电机 |
| check_motor_profiles.py | 驱动profile 0/1/2/3的目标编译 |
| audit_integrated.py | 构建日志、源文件注册、哈希、map和部分链接 |

这些工具在 [项目Tools](../../../Tools)。主机模型使用替身HAL/器件，不等于连接真实电机。不要把模拟结果199.99RPM写到实机稳态误差栏。

## 不使用CubeMX也能构建

在H743目录使用已安装的IAR路径：

```powershell
& 'C:\IAR Systems\Embedded Workbench 9.2\common\bin\iarbuild.exe' project/EWARM/H743_VisionGripper.ewp -make H743_VisionGripper -log all
```

`-make`增量构建；需要完整重建时用项目构建脚本。观察最终错误/警告、map中的摄像头区段与Flash范围，不只看终端退出前最后一个文件名。

## 编译成功与板上版本

新的HEX生成不会自动烧录。当前电机扩展验收状态写明未烧录，旧相机验证有另一个HEX哈希。项目汇总用哈希判断是否对应同一版本，不能依据“都是H743_VisionGripper.hex”认定相同。

烧录校验失败也要区分内容不一致与SWD读失败。旧现场曾独立读回Flash并按HEX逐字节比较才确认写入，保留了失败和复核日志。

## 本轮教学资料的验证

只核对文档链接、源码引用、独立示例的目标编译和固件未变化，不需要为写手册重新擦写板卡。结果见 [资料核验报告](../05_维护与证据/资料核验报告.json)。这里的测试层级是刻意分开的。
