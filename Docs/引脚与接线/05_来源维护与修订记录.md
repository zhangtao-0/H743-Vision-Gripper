# 引脚表来源、维护规则与本次修订

## 这次解决的问题

旧资料已有设备分配与108个引出信号CSV，但分散在适配规划、整合矩阵和电机手册；它们缺少统一的明显入口，也没有包含电源/地的完整板序视图。当前新增专门目录，并在项目根目录和总导航直接放入口。

## 唯一分配主档

[引脚资源.json](引脚资源.json)记录原理图排针事实与当前职责；Tools/generate_pin_reference.py生成按设备、按板子顺序、按GPIO索引、空闲清单和旧108行CSV兼容视图。不要直接手改生成的表格导致多份名单分叉。

从H743目录运行：

```powershell
python Tools/generate_pin_reference.py
python Tools/generate_pin_reference.py --check
python Tools/verify_pin_reference.py
python Tools/validate_learning_library.py
```

主档保留14个相关源码的SHA256，若源码变化，生成器会要求先审阅分配，不会悄悄套用旧“空闲”结论。确需新增或改分配时，先检查板载连线和实物，再修改板级绑定与完整初始化/IRQ/复用，审阅差异后更新主档、源哈希和表格。源哈希不能证明电气连接正确，更不能替代通断与波形测试。

板序的Pin1和全部脚号以[原理图排针截图](证据/U9_U10原理图排针.png)为依据。芯片数据手册的封装脚号和AF表是另外的索引，不拿GPIO名称的数字当排针编号。

## 分配状态的含义

| 状态 | 能否直接再分给别的设备 |
|---|---|
| 已分配 | 不能，已有软件责任，即使尚未接实物 |
| 板载专用 | 不能，PCB已连既有负载/功能 |
| 条件预留 | 不能直接借用；先决定驱动profile/释放方案 |
| 明确保留 | 保留未来职责，先同步规划 |
| 接口候选预留 | 接口未初始化，但候选方案已留；调整时记录 |
| 特殊脚待核对 | 不列普通GPIO候选，先核查模拟/调试等条件 |
| 空闲候选 | 当前资料未分配，仍需确认实物无外接，并核对目标功能AF等 |
| 电源/地/专用 | 不作普通GPIO |

## 本次核查与纠正

1. 完整登记U9/U10共120个位置和H1八针，而不只列108个MCU命名信号。U10-1/2/3/4均为GND，见[顶部放大图](证据/U10顶部供电核对.png)；不能照搬U9电源布局。
2. PG2/PG3/PC13明确归EC11与电机按键；PG4/PG5仍保留。PB14/PB15/PE10/PE12/PE13在无H桥profile0时仍是条件预留，不算免费资源。
3. PB8/PB9按既有多控制器规划标记接口候选预留，明确UART4没有初始化/接线。
4. PG8最终由LCD SPI初始化为SPI6_NSS AF5硬件片选；早期表的普通GPIO输出描述已纠正。vendor文件中遗留PE11等说明不能压过当前BOARD_LCD宏。
5. USB PA11/12已是当前CDC功能，不再沿用“将来才实现”的早期状态。
6. 旧设备CSV内通用“常见12V级”的舵机备注不适合已确定的STS3215-C001，改为指向当前硬件档案的C001规格。
7. PC2_C/PC3_C列特殊模拟焊盘，不直接等同于PC2/PC3的普通GPIO；调试与晶振保留。

修改前旧CSV存于[证据目录](证据/)。本轮只改变文档、数据表和离线生成/核验工具，没有修改生产代码、重新分配实物接线、烧录或制造物理PASS。结果见[表格核验](表格核验.json)。

最终核验：[源码/排针对照](源码与排针核验.json)检查50项引脚宏、108个既有引出事实；[表格核验](表格核验.json)检查完整板序与生成视图一致。整理过程曾遗漏PD12/PD13 PWM职责，已由源码宏核验拦截并修正，记录保留在证据目录；最终空闲数为39。
