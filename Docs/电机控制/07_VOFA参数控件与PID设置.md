# VOFA电机参数控件与PID操作流程

固件接口已实现。VOFA接收选择JustFloat；发送则使用ASCII文本+CRLF。这是两个独立设置，接收二进制波形不要求命令按HEX发送。现有工程提供接口及映射表；本页没有声称已经为用户导入VOFA布局。

具体滑块设置（VOFA+1.3.10、%.0f命令模板、鼠标弹起发送）见[滑块控件实际设置](08_VOFA滑块控件实际设置.md)。

## 参数绑定

| 控件 | 参数ID | 显示/输入方式 | 发出的完整命令示例 | 合法范围 |
|---|---|---|---|---|
| 目标速度 | 21 | 整数RPM；可在运行中修改 | @motor rpm 200（等效@param set 21 200） | 0～400RPM |
| Kp | 22 | 整数毫单位；1800表示1.8 | @param set 22 1800 | 0～100000，对应0～100 |
| Ki | 23 | 整数毫单位；5000表示5 | @param set 23 5000 | 0～100000，对应0～100 |
| Kd | 24 | 整数毫单位；0表示0 | @param set 24 0 | 0～100000，对应0～100 |

PID三个参数只能在控制器禁能时修改；转速可在运行中修改。范围是接口校验上限，不代表建议测试大增益。调整时沿用已经实测的1.8/5/0作为基线，每次只改一项。UI建议步长为转速5RPM、PID毫单位50；固件不要求数值必须是步长倍数。

VOFA若提供数值输入/滑块发送控件，应让发送文本形成上表格式；输入整数毫单位时，例如Kp控件输入2000，就发@param set 22 2000。若希望界面直接输入2.0，控件需要先乘1000再格式化为整数发送；具体占位符/表达式取决于VOFA版本，不能直接把VALUE等说明文字发送给固件。没有数值控件也可使用多条发送按钮，直接填完整命令。

按钮建议：启动=@motor enable；停止=@motor disable；绘图开=@motor plot on；绘图关=@motor plot off；换向=@motor reverse；查询Kp=@param get 22；查询Ki=@param get 23；查询Kd=@param get 24。直接启停指令不受Motor keys授权开关影响，模拟按键/旋钮则受该授权控制。

所有按钮使用单次发送，CRLF结束，不开启周期发送。多个配置命令逐条发送，间隔建议至少200ms，避免单行命令邮箱覆盖。

## 一次完整调参

先发以下命令，每行单独发送：

```text
@motor disable
@motor plot off
@param set 22 1800
@param set 23 5000
@param set 24 0
@param get 22
@param get 23
@param get 24
@motor rpm 200
```

关闭绘图后可以看到文字确认；param result=0代表接受，2代表忙（包括电机还在使能），3代表越界或条件不允许。查询结果value为毫单位，例如1800，不是1.8。确定参数正确后发送：

```text
@motor plot on
@motor enable
```

绘图主看CH1实际转速与CH2斜坡参考，CH0请求目标作为补充。输入@motor rpm 300改变运行目标，比较上升速度、超调、稳定时间、稳态误差；当前参考斜坡1000RPM/s，不能将参考本身的渐变误认为PID响应。CH4看PWM是否饱和，CH7看是否故障。绘图期间文字回复被抑制，命令仍执行。

要比较下一组PID，先@motor disable，再@motor plot off，修改参数并查询，再开启绘图和电机。停止绘图或关闭授权均不会停车。出现故障先记录@motor status并排查原因；清故障不是常规调参步骤。

## 保存为下次开机默认值

满意后停机、关闭绘图、确认其他机构也停机，再发送：

```text
@motor disable
@motor plot off
@profile save
```

profile save=0表示保存成功。它保存当前整套项目配置，包括电机目标及PID，也包含其他已接入开机配置的参数；不是单独保存电机的命令。保存不启动电机，复位后仍保持停机。临时测试不保存时，复位恢复已有保存值；没有保存配置则使用工厂值。读取已保存整套配置用@profile load，不能用profile clear作为仅恢复PID的替代。

恢复当前已测PID基线，只需停机后发送@motor pid 1800 5000 0。这会一次设置Kp=1.8、Ki=5、Kd=0，仍不会自动保存或启动。
