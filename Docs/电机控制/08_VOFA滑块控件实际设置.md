# VOFA+ 1.3.10滑块调参设置

本页专门说明滑块控件。2026-10-24已查看用户VOFA+1.3.10的右键菜单，确认存在“绑定命令”“事件与参数”“数值”等项，且事件参数默认显示为IEEE754小端字节。后续窗口未能继续定位，因此本轮只核实配置方法并保存文档，未替用户完成控件绑定，也未拖动滑块发送电机参数。

## 1. 先建立四条带占位符的命令

打开左侧“命令”栏，新增四条命令，命令本身使用Str/ASCII模式。命令内容如下，末尾必须有CRLF行结束（0D 0A）：

| 命令名称 | 命令正文，不含行结束 | 输入值例子 | 实际发出 |
|---|---|---:|---|
| Motor_RPM_slider | @motor rpm %.0f | 200 | @motor rpm 200 + CRLF |
| Motor_Kp_slider | @param set 22 %.0f | 1800 | @param set 22 1800 + CRLF |
| Motor_Ki_slider | @param set 23 %.0f | 5000 | @param set 23 5000 + CRLF |
| Motor_Kd_slider | @param set 24 %.0f | 0 | @param set 24 0 + CRLF |

这里使用printf浮点格式`%.0f`：滑块提供浮点参数，输出时保留0位小数，符合现有固件的整数解析。不要发送字面量VALUE，也不要用默认%f产生1800.000000：@param整数解析不接受小数点。公式换算不在命令中书写，本方案滑块直接使用毫单位整数。

注意：右下角临时发送框的CRLF选项，不应未经验证就当作左侧所有绑定命令也自动附加。应在每条命令自身设置行结束；若命令编辑器使用转义字符串，就在末尾加入其支持的\r\n，并检查一次TX内容是否以0D 0A结束。官方示例中Str命令使用printf占位符及\n，具体行结束显示以本机命令编辑器为准。只按回车退出编辑不等于命令数据包含回车。

## 2. 绑定滑块

每个滑块右键：

1. “名称”：分别命名为RPM、Kp×1000、Ki×1000、Kd×1000。
2. “数值”：设置from、to、step size，采用下表。
3. “绑定命令”：选对应的Motor_*_slider命令，不能绑定固定的“KP=1.8”预设，否则滑块怎么拖都只是重复固定值。
4. “事件与参数→模式”：使用浮点参数模式，与Str命令匹配。
5. “事件与参数”：关闭“滑块移动时发送”，开启“鼠标弹起时发送”。需要直接改右侧数字时，可开启“操作输入框时发送数值”。菜单中的点/勾应以当前选择状态为准。
6. 不绑定CH1等接收通道到这些调参滑块。调参滑块发送期望参数，波形的CH1才是接收实际转速。

| 滑块 | from | to（初次建议调试范围） | step size | 初始位置 | 数值解释 |
|---|---:|---:|---:|---:|---|
| RPM | 0 | 400 | 5 | 200 | 单位RPM |
| Kp×1000 | 0 | 5000 | 50 | 1800 | 1800=1.8 |
| Ki×1000 | 0 | 10000 | 50 | 5000 | 5000=5 |
| Kd×1000 | 0 | 1000 | 1 | 0 | 10=0.01 |

上表是建议初次调试的控件范围，不是PID接口全部允许范围。固件三项接口上限100000毫单位，不应因此把初次滑块范围设得过大。已测基线是Kp1.8/Ki5/Kd0，每次只改一项。

## 3. 验证一次确实发对

先保持电机禁能，用@motor disable；关闭波形用@motor plot off，便于看回复。

将Kp滑块置于1800并松开，检查发送区应为@param set 22 1800，随后应收到param result=0。再用@param get 22查询，返回value=1800。若仍出现00 00 E1 44等四字节数据，说明仍在Hex/裸浮点发送，没有完成Str命令绑定。若回复param result=2，检查电机是否仍使能；3表示参数或条件不允许；不要仅凭滑块画面变化认定固件接收成功。

验证输入框修改与鼠标弹起是否各只发送一次，确认结尾为0D 0A。固件命令按行解析；未加行结束的命令会等待，不会立即应用。

之后打开PID plot ONLY（或@motor plot on），启动电机，观察CH1实际转速、CH2参考，拖RPM滑块观察速度变化。

## 4. 当前固件限制与保存

- RPM滑块支持运行中调速。
- Kp/Ki/Kd滑块当前只支持禁能后设置。拖动它们不会自动停机、重新启动；运行中会返回BUSY，且绘图独占时该文字回复被抑制，看不到拒绝原因。当前不能把它们称为运行中在线增益调节。
- 建议再放两个明确按钮，分别绑定@motor disable和@motor enable。停止按钮不依赖复用授权，也不清空目标。
- 下一轮PID比较：停止→拖PID滑块并松开→启动。需要看修改回复时暂关绘图；图始终开着也能接收设置，但不显示文字确认。
- 保存满意配置：所有机构停机，发送@profile save。保存整套开机配置，含电机目标及PID；不自动启动。
- 关闭VOFA或关闭PID plot不等于停机，离开前显式@motor disable。
