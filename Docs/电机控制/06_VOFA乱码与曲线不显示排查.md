# VOFA收到乱码、曲线不显示的处理

PID plot ONLY发送JustFloat二进制波形，下方GBK文本窗把二进制当文字显示时会乱码，这是预期现象。修改GBK/UTF-8文字编码不会完成波形解析；应配置VOFA接收协议。

1. 使用HOST USB-TTL串口（最近实际COM9，以设备管理器为准），115200/8N1。原生USB CDC不是当前电机JustFloat输出口。
2. 在VOFA连接/数据协议设置选择JustFloat。成功解析后应有8路CH0～CH7。截图没有包含协议选择区域，因此不能仅凭截图确认当前选了哪种协议。
3. 清空旧接收数据和曲线缓存。如软件要求关闭串口才能换协议，只断开再重新打开连接；关闭上位机连接不会自动停机。
4. 保持屏幕PID plot ONLY为ON，或发送ASCII命令`@motor plot on`并带CRLF。二进制绘图不影响ASCII命令接收，期间HOST文字回复被抑制。
5. 绘图选择CH1实际速度、CH2有效斜坡参考，可再选CH0用户目标。成功解码后仍无可见曲线，检查通道勾选、采集是否暂停及坐标范围。
6. 本项目名义采样周期20ms（50Hz），图中Δt可设20ms，横轴约0.5秒/格或显示最近5～10秒。截图1ms/格太窄，不适合观察电机调速过程。Y轴启用自动缩放，或正转设0～450RPM，含反转设-450～450RPM；截图±5范围不能显示约400RPM的曲线。
7. 文本接收窗可暂停显示或隐藏，波形仍由JustFloat解析。想恢复文字帮助，发送`@motor plot off`。需要停车发送`@motor disable`；关绘图、关串口、关闭调试授权均不等于停车。

固件依据：project/App/modules/motor/motor_plot.c。每帧8个32位小端float，帧尾00 00 80 7F，共36字节。通道依次为请求目标、滤波实际RPM、有效斜坡参考、原始RPM、有符号PWM千分比、参考减实际误差、启用、故障码。Y轴单位混杂时先只选速度通道，不把PWM和启用码一起用于自动缩放。

本次核对为源码和用户截图分析，未占用串口、未改运行参数、未在用户VOFA界面实际操作。若仍无8路通道，应补充完整VOFA窗口中串口/协议设置区域，再定位解析配置，不能仅凭乱码认定固件数据错误。
