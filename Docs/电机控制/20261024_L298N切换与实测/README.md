# L298N接线、当前版本与实测边界

> 最新结果：闭环已通过；400目标末段平均399.78RPM，模拟按键启停/旋钮调速/换向通过。[2026-10-24最终记录、曲线与代码入口](独立驱动诊断/README.md)。当前停机fault0。以下内容为先前阶段记录，保留失败证据。

## 当前接线

| 信号 | MCU/端子 | 说明 |
|---|---|---|
| ENA | PB14 / U9-45 | 拔ENA使能跳帽；20kHz PWM |
| IN1 / IN2 | PE10 / U9-37；PE12 / U9-39 | 方向信号 |
| OUT1 / OUT2 | 电机M+ / M− | 只接动力绕组 |
| VS（常标+12V） | 用户报告10.3V | 动力电源；未用表实测 |
| GND | 驱动/MCU/编码器共同地 | 不以M−代替逻辑地 |
| 5V-EN | 用户确认保留 | 与ENA跳帽不同，常见模块使能板载稳压；5V端不接MCU3.3V |
| 霍尔A | **PA8 / U10-47** | 已替代PE9，TIM1_CH1/AF1 |
| 霍尔B | PE11 / U9-38 | TIM1_CH2/AF1 |
| 编码器VCC | **开发板+5V / U9-3或4** | 用户已为供电对照改接；10.3V不能接此处 |
| 编码器GND | 共地 | 供电/输出仍需电气核查 |
| PE9 / U9-36 | 停用并预留待查 | 拔线且普通输入上拉仍读低；不能据此直接判MCU损坏 |
| PE13 / U9-40 | L298N不接 | 原TB6612 STBY保留备用 |

STM32数据手册已核对PA8和PE11为对应FT数字输入，GPIO内部上下拉已关闭并由寄存器确认，以符合5V容限条件；编码器按用户资料允许3.3～5V且有内部上拉。当前是5V对照配置，不代表已测得其实际供电或全部输出波形正常。条件见[5V依据](编码器5V对照依据.md)。

L298N逻辑VSS应为5V，GPIO高电平2.3V起，3.3V控制信号可用。L298N有导通压降，电源10.3V不等于绕组始终得到10.3V，更不能用平均PWM换算代替实测电压。芯片资料：https://www.st.com/resource/en/datasheet/l298.pdf 。

## 已完成的实物工作

1. 用户切换L298N、确认ENA跳帽拔除/接PB14、5V-EN保留。原板内profile2的PWM/方向接口兼容L298N，首次实测目标400、参考达到400、PWM至95%；用户确认持续转动，但计数仅增加约1，不能称闭环通过。
2. 发现旧保护“任意一次脉冲重置计时”可被稀疏跳变绕过。已改为努力输出时每300ms要求最少2计数且达到参考预期5%的**净方向计数**，来回抖动不能抵消无反馈条件。fault1现在涵盖无反馈/进展不足，不等于精确定位哪根线坏。
3. ST-Link重新插电脑后恢复。已备份2MB、烧录并校验新profile1和按键授权版本，独立读回核验通过；没有覆盖UI/标定配置扇区。
4. 读PE9/PE11和TIM1实际寄存器：GPIO复用/上拉/SMS3/CC1E/CC2E正确；PE9拔线后仍低，PE11变高。普通输入隔离PE9仍低，故保守停用；PA8经ST数据手册及排针表核对后替代A。A/B可分别配置端口，不再要求在同一GPIO端口。
5. PA8/PE11拔线时均可拉高，TIM1随拔插计数变化；接回后低速短测触发保护。编码器VCC随后依用户操作改为+5V，并关闭内部上下拉；默认PID试验仍在未稳定起转时停止，不能单凭这项断定编码器坏。
6. 观察到部分诊断停机后计数增加并最终稳定；有可能与惯性转动/迟起转有关。又做了最多0.7秒、保留保护的临时Kp12/Kp40、Ki0诊断，均触发保护。原始数据保留，未因此延长保护或永久改PID。

当前默认Kp1.8/Ki5/Kd0、目标400已恢复，输出禁能、PWM0、fault1保留。**动力通路能转、闭环验收未通过**，不是“L298N更换后PID已调好”。

## 按键、指令和VOFA

已烧录版本支持@debug status、@debug motor on/off、@debug sts on/off；两权限上电OFF，屏幕KEY3+4快捷到DEBUG页，退出页面保留权限。电机KEY5启停/KEY6单击减5双击加5、KEY7短启停长换向及旋钮功能按原设计，但当前反馈尚未验收，先不要用这些方式反复启用。

波形使用CH340的COM9、115200/8N1、JustFloat八通道；COM号会变，按设备管理器为准。@motor plot on后HOST文字回复受独占门控；状态查询前用@motor plot off或@quiet。命令不要连续挤在同一毫秒发送，至少等待处理完毕，否则单行邮箱可能丢后续命令。需要停机先@motor disable，@quiet本身不停车。

本轮实测脚本最终以文本状态或二进制enabled=0/PWM=0确认停机。首次脚本exit0仅表示传输过程无异常，反馈质量已另外标FAIL；不把串口成功当PID成功。
