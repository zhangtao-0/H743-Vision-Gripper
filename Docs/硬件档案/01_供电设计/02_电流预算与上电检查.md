# 电流预算、接线与分阶段上电

## 电压、电流和功率分别决定什么

电源电压要落在设备允许范围；额定电流表示电源能稳定提供的能力，不会因为标“5A”就强迫设备一直吸收 5A。能力不足会掉压、复位、保护重启；电压过高则即使电流额定很小也不合适。

先分电压轨算：`I轨峰值 ≥ 同时工作的各设备峰值电流之和 + 余量`。不同电压的电流不能直接相加，先算功率 `P=V×I`，再考虑 DC-DC 效率：`I输入≈ΣP输出/(η×V输入)`。限流阈值还须低于薄弱导线、接口和模块能承受的故障电流。

| 支路 | 已知数据 | 不能据此省略的核对 |
|---|---|---|
| 主板 5V + 视觉 | 当前 USB 工作；没有测量整机峰值 | 记录启动/背光/采集/SD 写入同时发生时的电流与最低电压 |
| 板外 3.3V 模块 | 板卡说明对外不超过 500mA | 已有外设、温升和供电余量；HC-08 官方要求供电能力至少 100mA，但它不等于恒定耗电 100mA |
| MG310 动力 | 用户截图：额定 ≤0.5A、堵转 ≤2A | 电源和 H 桥覆盖起动瞬态；不允许用持续堵转测试确认额定能力 |
| STS C001 | 官网表列 6V 空载 0.15A、堵转 2A | 7.4V 峰值及批次参数未确认，多舵机同时起动、堵转保护策略 |
| 蓝牙 | JDY 子型号待确认；HC-08 V3.1 有工作/睡眠模式 | 底板 LED、稳压器和无线突发电流，不能只用睡眠电流预算 |

例如动力轨如果同时有一台电机和一台舵机，按已有资料其起动/异常电流可能明显超过任意单机的空载值。先用完整工况数据相加，再选择连续输出、瞬态能力、散热均合适的电源。现有 STS 数据只在 6V 给出，不能把“7.4V 4A 电源必定足够”写成已验证结论。

供电连接器、导线截面积/长度、接触电阻会造成 `ΔV=I×R`。在电源端量到 7.4V，而执行器端启动时掉到 5V，是完全可能的；应在负载插头处量动态最低电压。示波器接地必须明确参考，避免探头地夹短接 H 桥输出。

## 上电前确认

1. 先断电，辨认每个正负极、VCC 与信号，不用线色代替端口定义。核对转接板的 USB 5V 与舵机动力端之间是否相通。
2. 不带负载调好 DC-DC，用表确认输出与极性；清楚限流、保险、欠压/过压、反接保护的位置。
3. 首先只供主板与低功耗设备，确认 5V/3.3V 和温升；记录 USB/外供切换方式。
4. 编码器按 3.3V 供电，手动轻转验证 A/B 及计数，不驱动电机。
5. 接入已选 H 桥前核对 3.3V 输入识别阈值、真值表、默认关闭状态、限流和散热。固定电机，移开负载/夹爪危险行程，以低输出短时试验校准反馈符号。
6. 舵机先确认 ID/波特率、原始回应和电压反馈，再限制速度/行程做动作。通讯供电正常并不代表带载动力供电充足。
7. 最后组合运行，观察视觉帧、串口错误、复位、温度与电源压降，记录证据。

动力电流不要经杜邦线和主板细排针随意转接。驱动端近端储能/去耦、电机抑制、短回路和合理布线应按驱动板厂商布局要求落实；不是任意并一个“大电容”就完成。电机降速和舵机回拖还可能回馈能量，电源/驱动能否处理回灌同样要查。

## 从现象判断电源问题

屏幕花屏、蓝牙断开、USB 重新枚举、MCU 复位可能与瞬态供电有关，也可能是驱动/时序问题。先做对照：关闭动力、单设备供电、负载端测量、记录复位原因。不能只因现象像干扰就无限修改 PID 或 LCD 初始化。

实际记录使用[硬件验收模板](../03_替换与验收/02_实物验收记录模板.md)，未经测量的电流项填写“待测”，不填经验值冒充实测。
