# 自定义开机默认值：保存、加载和清除

## 使用流程

进入参数调节，编辑并确认各项运行值；停止STS/MG310运动；进入默认参数页，选择`SAVE boot profile`，在确认页选EXECUTE并确认。成功后SYSTEM页显示Boot=1及序列。它保存当前快照，不是自动保存每次按键。

`LOAD boot profile`立即加载已保存快照到RAM，仍不自动使能电机；STS栈未就绪则保留待应用配置，栈建立后再应用。`CLEAR boot profile`写入更高序列的删除标记，让下次开机使用固件默认；它不立刻恢复当前RAM，也不清机械限位。要立即恢复，分别使用Restore STS RAM/Restore motor RAM。

## 保存哪些字段

- STS运行参数ID2–20：档位、速度、转矩、反馈/打印周期、释放权限等。参数ID0/1对应张开/闭合端点，**不进入这份开机配置覆盖**，沿用独立机械限位机制；菜单里这两项只读。
- MG310目标RPM、Kp/Ki/Kd（千分之一编码）和浮点CPR。CPR保持原浮点精度，不拿`cpr1000`报告值当输入。
- 不保存使能、运行状态、累计计数、故障、GPIO映射、驱动profile、摄像头临时分频和菜单位置。开机即使恢复非零目标RPM，电机仍禁能，必须显式启动；无H桥profile0照常拒绝。

离线保存时：尚未建立STS栈则保留上一份有效记录的STS部分；首次无旧记录时采用固件默认。已建立栈时读取运行参数。它不会为保存参数而自动探测/启动夹爪。STS ID12有历史“初始10ms、写入最小20ms”差异，加载保存的编译初始10ms时保留原初值；显式运行修改仍遵守20ms下限。

配置应用顺序为电机初始化→读取并验证开机配置→恢复电机参数但保持禁能；STS控制初始化与限位加载→只应用ID2–20。恢复STS RAM默认值时保留当前OPEN/CLOSE端点。参数恢复不是清故障，也不是自动动作。

## 分区与记录

| 区域 | 地址 | 用途 |
|---|---|---|
| 固件ROM | 0x08000000–0x0817FFFF | IAR链接器限制，避免代码进入配置区 |
| Bank2 sector4 | 0x08180000–0x0819FFFF | 开机配置A，128KiB |
| Bank2 sector5 | 0x081A0000–0x081BFFFF | 开机配置B，128KiB |
| Bank2 sector6/7 | 0x081C0000–0x081FFFFF | 原机械限位双份记录，保持独立 |

每份开机记录160字节，包含magic、版本1、递增序列、有效/删除标记、参数、CPR编码、预留位和CRC32，正好5个H7 32字节Flashword。读取只选CRC/版本和范围有效的最新记录；忽略版本不认识或损坏的记录；两份均无有效配置时回到固件默认。

保存擦除旧/备用扇区，完整写入并回读校验成功才更新RAM保存状态；失败保留另一份。CLEAR同样写一份有效删除标记，不先擦掉两份。启动和读取不会擦写Flash；Bank swap打开时拒绝写入，防止物理bank判断错误。

写入期间用MotorService维护门控防止PC13/其他入口重新使能电机，并要求STS不在运动。Flash操作是同步维护操作，不是后台无限重试；减少频繁保存以控制擦写次数。电源质量、Flash耐久和真实掉电行为仍须实测。

## 固件下载注意

本版没有实际烧录。以后下载时，若工具执行整片擦除，开机配置和机械限位都会丢失；仅保留代码区下载也必须看工具实际擦除范围。升级配置结构时提高版本并明确迁移策略，不能只改C结构体大小。不要修改地址宏却忘记链接区边界和扇区号。

## screen-ui-v2兼容扩展

原记录大小/版本和扇区不变，reserved[0]=VIEW标记、reserved[1]低6位保存LCD方向、图像方向、左右镜像、上下翻转；旧零预留记录方向按0。SAVE可保存这些设置，LOAD/启动恢复方向。不恢复CLAW_PRINT启用位，避免旧配置重新刷屏；用户本次运行仍可手动启用。不保存冻结画面和边缘开关。详见[兼容记录](20261022_交互与图像修订/修改记录.md)。
