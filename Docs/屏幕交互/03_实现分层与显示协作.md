# 实现分层与摄像头显示协作

当前screen-ui-v2的分类帮助、独立图像查看、旋转/镜像与静默行为见[本轮修订](20261022_交互与图像修订/README.md)。下面初版叙述保留原设计背景；以当前操作手册为准。

| 模块 | 职责 | 不应放入的内容 |
|---|---|---|
| [ui_core](../../project/App/modules/ui/ui_core.c) | 页面栈、选择/滚动、草稿、确认、快捷快照、文本视图 | HAL、引脚和设备句柄 |
| [ui_input](../../project/App/modules/ui/ui_input.c) | 已去抖双键→短按/长按/组合语义，释放抑制 | 具体业务动作 |
| [ui_port](../../project/App/modules/ui/ui_port.c) | 当前参数、命令、默认动作、状态绑定 | UART帧拼接和屏幕像素 |
| [ui_service](../../project/App/modules/ui/ui_service.c) | 生命周期、有限中文标签、按行差分绘制、预览窗口 | 另建一份电机PID/夹爪状态机 |
| [ui_settings](../../project/App/modules/ui/ui_settings.c) | 自定义开机参数收集、验证、应用、运动门控 | Flash地址/擦除算法 |
| [ui_profile](../../project/App/modules/ui/ui_profile.c) | 固定记录、CRC、版本、最新序列判断 | 硬件访问 |

## 典型调用顺序

`Key_Task → UiService_Input → UiInput_Sample → UiCore_Event`，只生成或推进导航语义；按确认时通过UiOperations进入业务适配。主循环集成任务中`UiService_Task`先决定显示窗口、最多绘制两条变化文本行，然后`BoardCamera_Task`按条带复制图像。

App初始化在MotorService后加载开机配置；P3配置ID在线后创建原STS业务栈，再应用保存的STS运行参数，最后启动原命令任务。持久化加载没有替代P3就绪条件。

## 为什么快捷不能只存一个page编号

编辑页还依赖父列表、选中项、滚动位置、原值和草稿；确认页还依赖具体动作与CANCEL/EXECUTE选择。UiModel保存完整UiLocation栈。快捷入口构造正常`HOME→MONITOR`路径；快照另存，返回行为既可沿正常祖先，也可显式恢复快照。

离开观测页的常规返回会清除快照。快照不跨断电保存，不覆盖设备实时状态；只保存UI上下文。恢复编辑后要重新检查原值，防止后台串口/EC11更新被覆盖。

## 视频采集与LCD预览分开

[BoardCamera_SetPreview](../../project/App/platform/board_camera.c)控制是否绘制以及窗口位置/高度；`BoardCamera_Enable`仍控制采集使能。菜单默认不画视频，但可继续采集计数。图像查看页使用y=32、144行窗口，将完整240×240帧等比例缩到144×144居中显示，条带宽240并补黑边；CAMERA观测页只显示诊断；页眉/状态/按键提示独占其余区域。

改变窗口时放弃尚未画完的旧预览，不同时把同一帧交给新DMA覆盖。完整帧判断仍保留帧标志、DMA ready、无错误、NDTR=0的条件。离开预览后文本层清掉旧图像区域；原集成模块的底部状态行在UI模式下停用，避免第三方覆盖。

## 后续扩展

增加页面先扩展纯模型和操作事件，再在端口层提供参数/动作。新命令遵守取消优先、确认后再检查实际就绪。要新增专用四方向键，可以替换ui_input/板级绑定，UiCore的NEXT/PREV/OK/BACK/SHORTCUT保持不变。中文标签字模是本机字体生成的31字子集；ASCII复用既有固件字体，参数名称对应代码标识。
