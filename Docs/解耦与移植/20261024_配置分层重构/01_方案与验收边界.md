# 配置分层与适配层重构方案

## 目标

将硬件事实从业务与Core初始化中收敛到可选板级配置，按功能分成合理数量文件；通过同一配置驱动UART角色、初始化、GPIO复用、IRQ及校验，避免改了句柄表却没有改底层的情况。按键保持物理/模拟同一业务，屏幕KEY1～4及授权语义不变。硬件配置是编译期事实，与运行期参数、Flash保存值、VOFA控件映射分别维护。

## 现状

已有platform_hal、BoardUartRole、board_config、board_devices，仍存在UART在Core/main、MSP、IRQ及board_resources重复配置；GPIO与时钟硬编码；Flash页地址在integration_config，Flash擦写实现进入UI目录；角色头文件带HAL依赖。旧HAL的F103分支不代表整套H743工程已具备F103能力。

## 实施分组

1. 配置入口：target_config选择一个目标头，目标头选择SDK入口和board_profile。
2. 当前板board_profile仅汇总六组：io（按键/LED）、serial（UART角色与引脚/IRQ/时钟）、motion（电机/编码器/旋钮/PWM舵机）、vision（屏幕/摄像头）、storage（SD/QSPI/内部Flash分区）、system（芯片时钟/定时器时钟/能力）。保留旧board_config/board_devices为兼容入口，不保存第二份配置。
3. UART描述表作为唯一来源，由适配层生成句柄、绑定、初始化、MSP、IRQ；Core只调用适配入口。
4. 业务保留现有API；输入GPIO可逐键配置电平和上下拉；电机时钟约束和分辨率从板配置读取。
5. 内部Flash独立port，UI配置及夹爪限位使用同一受限双槽存储接口，布局/CRC/版本不变；不擦写实物Flash。
6. 统一表格：功能→配置→适配实现→业务API→SDK/能力边界；教程给同系列换引脚、换UART、换蓝牙、换MCU四条步骤。

## 验收

保留重构前备份及哈希；主机测试覆盖角色改绑的初始化/MSP/IRQ一致性、非法角色/重复硬件绑定拒绝、通用参数和输入语义、存储页边界及Flash写失败后的旧槽；所有三种IAR摄像头配置、已有重要回归、引脚和教学资料核验。保留现有引脚、波特率、IRQ优先级、NOPULL与Flash地址，差异报告逐项检查。除非后续需要独立物理验收，本轮不占用运行串口、不烧录、不启动电机或舵机，不把构建成功当跨芯片/实物通过。

## 实际移植边界

相同HAL家族换引脚/角色应集中修改板配置；跨HAL家族还必须提供相应芯片backend、startup、SDK、链接脚本、中断和DMA/Cache实现。F103无DCMI/内存容量等能力不能靠宏伪装；能力不足要显式禁用或改用另一硬件接口。只交付实际H743重构，其他芯片不标已适配。
