# 机构接口与通信契约草案

**状态：规划草案，当前固件不支持下列新帧/接口。** 与[已实现指令](../指令手册/README.md)分开维护，实施时再给正式版本及可复制字节示例。

## H743内部先建立统一机构层

建议增加独立 `mechanism` 服务，调用链：按键/屏幕/控制台/无线意图 → 输入仲裁与任务检查 → 机构目标/轨迹 → 本地PWM、STS或远端节点适配器。关节配置保留单位、方向、零点、限位、速度与所用执行后端；不让菜单直接发UART字节。

| 建议模块 | 责任 |
|---|---|
| mechanism_config | 机构ID、关节表、后端/节点/通道映射、标定和保护策略；板级资源仍在platform |
| mechanism_service | 统一使能、提交/取消、状态；检查整组目标，处理任务生命周期 |
| node_link | 版本/能力协商、连接状态、会话、重试、心跳、故障诊断 |
| node_protocol | 字节分帧、长度、CRC、字段编解码，不包含HAL |
| remote_pwm_backend | 将关节目标经标定转换为通道脉宽，按组提交；解释节点状态 |
| intent_adapter | 未来C3网络/语音消息转为受限请求，不直接操作执行器 |
| platform | UART角色、句柄绑定、IRQ/缓冲，业务看不到huart4 |

同一关节同一时刻只有一个控制者：本地手动、自动任务或远端请求按模式仲裁，停止/故障优先。不能让新菜单服务与旧F5/蓝牙/按键路径同时写同一通道；新增机构层后，旧入口也应汇入仲裁。

## 节点能力与状态

握手返回node_id、协议版本、固件版本、boot_id、channel_count、支持的插补/反馈能力、配置revision/hash、每通道脉宽范围、是否有真实位置反馈。H743预期6路而节点报8路时也不能自动激活多出的通道，需配置匹配。

状态至少分 `OFFLINE → HANDSHAKE → DISARMED → READY/ARMED → EXECUTING`，以及 `FAULT`；READY的含义须在实现时固定，建议只在授权输出后使用ARMED。任一端复位都重新握手，撤销使能，清除旧会话未执行任务。协议版本/机构配置不兼容，停在DISARMED。

能力查询和心跳不隐式使能。普通PWM输出只回报commanded_us/estimated_us、轨迹进度和故障，不返回伪造的实际位置。状态中用feedback_valid=false明确表达无真实反馈。

## 首版通信建议

物理层：专用点对点115200/8N1；二进制内容使用 **COBS编码，0x00作为帧结束符**，避免负载中的特殊字节被当作边界。解码后再验证长度与CRC；超长或不完整帧丢弃并恢复到下个分隔符，不执行半帧。

候选原始帧字段：version(u8)、type(u8)、src(u8)、dst(u8)、session_id(u32)、seq(u16)、payload_len(u16)、payload(≤128B)、crc16(u16)。多字节字段统一小端；CRC候选为CRC-16/CCITT-FALSE(poly0x1021、init0xFFFF、不反射、xorout0)，覆盖version至payload。字段、COBS与CRC需要两端共同测试后才能冻结v1。

| 消息 | 请求与行为 |
|---|---|
| HELLO / CAPS | 协议版本、H743会话随机/唯一标识、节点boot_id、能力、配置摘要；会话身份用于防旧动作重放，不是网络身份认证 |
| ARM / DISARM | 明确输出授权；节点只有收到当前会话ARM并通过自身检查才输出 |
| SET_GROUP | command_id、duration_ms、count、若干(channel,u16 pulse_us)；整组校验后原子接收，各通道同一插补起点 |
| STOP | 丢弃待执行轨迹并进入已配置停止策略；独立于普通动作队列，轮询每次先处理 |
| HEARTBEAT / STATUS | 双向存活、队列、当前命令、插补进度、估计脉宽、故障、重启/掉线计数 |
| ACK / NACK | 已校验接受或拒绝；拒绝含版本/范围/未使能/队列满等原因 |
| PROGRESS / DONE / FAULT | 轨迹执行状态；DONE只表示软件插补结束，无反馈时不声称物理到位 |

SET_GROUP用微秒，不用原程序含混的“角度或14位PWM值”。H743统一关节角度和标定，节点再检查自己的硬限制；每通道范围独立，未知型号不能默认全部500–2500µs。整组有一项越界就拒绝整组，避免只动部分轴。

节点从最后已输出的估计目标插补到新目标。SET_GROUP携带duration而不是要求H743每20ms刷新所有脉宽；节点持续输出PWM，H743只在目标改变时发组目标，另发心跳。多节点首版不承诺同周期同步；若需要跨机构严格同步，再加时钟同步、定时启动及误差验收。

## 可靠性与故障

初期一次最多一个待确认动作请求，ACK超时重传相同session/seq/command_id。节点缓存该会话最近响应，重复包只重发响应，不能重启同一轨迹。seq回绕前更新会话且处于停机态；节点重启后的boot_id变化强制重新握手。旧会话包、过期意图和无效CRC不更新控制租约。

建议心跳200ms、失联阈值1000ms作为首轮测试起点，非已测定参数。只有H743发送的当前会话有效心跳/合法控制更新节点控制租约；节点自行发送STATUS不代表核心仍在线。STOP、失联检查不可被动作循环或WiFi阻塞。轮询调度需给出最坏检查间隔并实际测量。

失联时清待执行动作，停止轨迹推进并锁定故障；“保持最后脉宽”“停止PWM”“切动力”对不同负载影响不同。机械臂突然失去力矩可能下落，保持夹紧也可能持续堵转，**未定义并实测该机构故障策略前不允许ARM**。首次验证应卸载或支撑机构。通讯STOP不是独立硬件急停，需断动力的要求由实际电源/机构设计实现。

恢复连接不自动继续旧任务；重新读取状态、确认支撑/当前位置估计是否可信并授权。任一方断电后的旧软件角度不能证明真实姿态，未知时拒绝需要可信起点的轨迹，先完成受控校准流程。

## 带宽与网络入口

115200/8N1约11520字节/秒/方向。即使保守按一帧50字节、50帧/秒估算，单向约2500字节/秒，占约22%；首版采用事件目标+心跳，通常远低于此。状态回传可先用10Hz并测实际帧长；全双工两方向分别算，未来半双工总线则需把请求/回复/转向/重试一起预算。不要将PWM50Hz刷新率等同必须50Hz跨板发包。

C3未来传的是意图和参数，H743重做权限/范围/状态检查。CRC仅用于检错，不能抵御伪造；无线认证、连接授权与消息过期属于入口职责。第一版不提供网络直通任意机构帧/Flash写入能力。
