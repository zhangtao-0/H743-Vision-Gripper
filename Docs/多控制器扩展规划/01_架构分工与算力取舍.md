# 架构分工与算力取舍

## H743负责决定动作，机构节点负责可靠执行

以当前H743工程为主线，上层统一采用“设备、关节、动作”的名字；不让界面和业务代码关心某个舵机究竟由TIM4、STS总线还是远端MCU输出。先建立一个执行机构，再在相同契约下增加机构。

| 层级 | 当前推荐职责 | 不能冒充的能力 |
|---|---|---|
| H743控制核心 | 统一模式/参数/屏幕/按键；输入仲裁；机构坐标和运动学；整体动作顺序；权限、限位、任务超时、故障汇总 | 无反馈PWM舵机的真实位置不能从发送值直接得出 |
| ESP8266机械臂节点 | 本地通道映射与脉宽限制；组目标原子接收；按持续时间同步插补；PWM；心跳与失联保护；状态上报 | 不再同时接受独立WiFi网页自动脚本来绕过H743 |
| ESP32-C3可选入口 | WiFi/BLE通信、按钮/手机/网页输入、协议转换；将识别结果转换成受限任务请求 | 自然语言或网络返回文本不能直接变成任意脉宽/Flash写入 |
| F103备用节点 | 后续另一套机构的定时器PWM、编码器与局部闭环，或替换ESP8266 | 暂无第二机构时没有必须上电联网的理由 |

MG310的编码器采集、100Hz PID和保护目前继续留在H743。只有物理布局或独立实时性确有需要，再将整套“采样+PID+功率接口+保护”一起下放，不能只把PWM下放而把高速反馈绕远路送回。

## 三种方案的选择

| 方案 | 适合条件 | 代价与决定 |
|---|---|---|
| H743直接输出多路PWM | 机构与核心很近、可用定时器/引脚足够 | 结构最简单；普通舵机通常自带内部位置闭环，H743不需要替每个舵机做外部PID。当前已有两路TIM4，未见证据证明算力不足 |
| H743直连专用PWM芯片 | 扩展板实际带PCA9685一类器件，并确认电路 | 不必增加一块MCU，但要确认芯片、I2C地址、电平、PWM频率/分辨率及失联时输出行为；不能凭“八路扩展板”认定就是PCA9685 |
| H743+独立机构MCU | 机构可拆卸、线束需集中、希望局部插补/看门狗/独立测试 | 符合本次模块化目的；增加协议、版本、重启和供电管理成本，先只做一个节点 |

推荐第三种不是因为8路50Hz脉冲必然耗尽H743，而是希望形成独立机构边界。若最终只有固定的一套机械臂，直接驱动或专用PWM芯片也可能更合适。

## CPU使用率不是设计目标

额外MCU提供的是连接点、定时资源、故障边界与机构可替换性。低CPU利用率不一定浪费；为了“用满”而增加无必要的跨板链路，会增加调试与故障概率。

第一阶段只运行H743和已有ESP8266。C3有明确无线/语音输入需求再加；F103留备用。不要做“C3→8266→F103→H743”的多级转发。每个节点通过清晰的控制接口参与，机构之间由H743协调。

## ESP32-C3上的AI要分层理解

用户确认是 **ESP32-C3**，不是ESP32-S3，也不是STM32F103。官方ESP-IDF说明C3有2.4GHz WiFi、BLE和单核RISC-V处理器。[官方芯片入口](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c3/about.html)

| 想要的能力 | C3上的现实规划 |
|---|---|
| 手机/网页按钮或文本命令 | 首选先做，C3转换成结构化意图送H743 |
| 离线唤醒词 | 乐鑫ESP-SR已提供面向C3等无PSRAM/无SIMD芯片的WakeNet9s；需麦克风/音频链路和对应示例验证，裸板不等于有语音输入 |
| 多条离线中文语音命令 | 不能把ESP32-S3的MultiNet文档直接视为C3支持；先核实当前SDK、模型目标和资源消耗。此次未证明C3可运行目标命令模型 |
| 开放式自然语言/大模型对话 | 首期放在电脑、手机或服务端，C3只做联网/消息桥接；不把完整对话大模型作为C3板载方案 |
| 视觉识别 | 当前摄像头采集仍在H743。先明确识别目标、图像尺寸、模型预算，再决定H743小模型或外部推理；不同时搬动摄像头链路 |

[ESP-SR官方仓库](https://github.com/espressif/esp-sr)记录WakeNet9s支持C3；[ESP32-S3 MultiNet官方文档](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/speech_command_recognition/README.html)说明的是S3命令词识别。唤醒词识别、命令词识别和开放式对话不是同一种功能。

示例：C3输出 `intent=OPEN_GRIPPER, request_id=42, expires_in_ms=500`；H743先检查机构在线、控制权、工作模式和行程，再生成关节轨迹。若需要“抓取红色物体”，H743还要有识别位置、坐标变换、可达性与动作规划；有一句意图文本并不自动具备这些能力。

AI低置信度或不支持的请求拒绝执行。先限定少数白名单意图，如观测、停止、请求张开；涉及动作仍服从H743统一使能与仲裁。识别结果无权清故障、绕过限位或恢复失联后的自动运行。
