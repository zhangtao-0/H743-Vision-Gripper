# H743资源与连接方案

所有新增引脚均为**设计候选**，未写入固件、未实物连线验证。当前资源依据[设备引脚矩阵](../整合交付/02_设备引脚与功能矩阵.md)和[108引脚引出表](../适配规划/03_硬件规划/板级引出与用途表.csv)，不是按芯片引脚“理论空闲”直接分配。

## 第一个执行节点使用专用UART4

| 设备侧 | MCU引脚 | 板上引出 | 对端连接 | 状态 |
|---|---|---|---|---|
| H743 NODE0 TX | PB9，UART4_TX，AF8 | U10-22 | ESP8266 GPIO3/RX0 | 候选，当前表为空闲 |
| H743 NODE0 RX | PB8，UART4_RX，AF8 | U10-19 | ESP8266 GPIO1/TX0 | 候选，当前表为空闲 |
| 通信参考地 | 已确认的开发板GND | 按板上GND标识/原理图 | ESP8266 GND | 非隔离UART须共地 |
| ESP8266舵机CH0–5 | GPIO5/4/0/16/14/12 | 取决于扩展板走线 | 对应六个PWM信号 | 原程序映射，须实物复核 |
| 舵机动力 | 扩展板舵机电源母线 | 实际端子待确认 | 按具体PWM舵机电压 | 与逻辑电源分别预算 |

依据本地ST数据手册DS12110 Rev11：第86/87页PB8/PB9功能，第90页Table10中AF8=UART4_RX/TX；[本轮查表图](06_证据/H743_UART4_AF表.png)。UART4的PB8/9与FDCAN1等候选复用，采用后不能同时再给这些用途。PC10/PC11已用于SDMMC1，不选它们作串口。

保留现有USART1/PA9/10上位机、USART2/PA2/3 STS、USART3/PB10/11 JDY-31。当前源码只有这三个角色，UART4并未初始化，不能现在接线就期待能控制ESP8266。

ESP8266官方Arduino Core说明：UART0默认GPIO1 TX、GPIO3 RX；UART1常用GPIO2只有TX能力，不能当成第二条完整收发UART。[官方串口说明](https://arduino-esp8266.readthedocs.io/en/latest/reference.html#serial)

不要直接将UART0 swap到GPIO15/13：当前原程序这两脚用于按钮，GPIO15又涉及启动条件。先选默认UART0；板载USB转串口若也驱动RX，烧录/调试时应切换或隔离，避免两个TX并接。具体跳线方法须看实际ESP8266板型。

逻辑信号采用3.3V TTL UART，初期115200/8N1。TTL单端UART只作为板内短线、共地连接；线长、噪声和地电位条件变化后要重新选物理层，不能靠调波特率承诺远距离可靠。

## 电源单独设计

UART的TX/RX不传动力。不能用H743的3.3V引脚供整排舵机，也不能把STS C001或MG310的7.4V直接用于未知PWM舵机。每种舵机按完整型号核对电压和峰值电流，计算同时动作电流、线缆压降、母线与端子额定。

ESP8266模块核心供电和开发板USB/VIN输入不是同一范围；先核对所用开发板稳压电路。扩展板是否将V+/VIN/USB并联、有没有电源选择或隔离尚未知，因此这里只指定信号连接，不虚构它的安全动力口电压。结合[现有整机供电档案](../硬件档案/01_供电设计/01_开发板与整机供电.md)制定唯一供电路径及共地拓扑。

## 以后增加节点

首期一条UART只接一个节点。两块从机的TX不能直接并接到H743 RX。

| 阶段 | 选择 | 增量代价 |
|---|---|---|
| 1个机构 | UART4点对点 | 最少改动，先证明协议与故障行为 |
| 再加C3无线入口 | 可评估独立UART8 PE1/TX、PE0/RX | 这组目前在引出表空闲；具体AF/初始化/板卡走线在实施时再次核对。暂不占用 |
| 多个分布式机构、线束较长 | 评估RS485主从总线或CAN | 每个节点需要匹配收发器，补终端/拓扑/轮询或仲裁/供电设计；不是只更换软件协议 |

PB6/PB7和PG4/PG5继续保留，其他原预留资源不在本轮分配。若未来用PB8/9的FDCAN功能，则必须迁移UART4候选并重审；模块角色名称不变，板级绑定变化。

## 手动HAL配置时的实施清单

后续编码时新增 `BOARD_UART_NODE0` 角色和对应平台绑定，业务不得直接引用huart4。需要依次处理：UART内核时钟来源与分频 → GPIOB时钟 → PB8/9 AF推挽/AF8 → UART4外设时钟与115200/8N1/TX_RX → NVIC及UART4_IRQHandler → 平台唯一回调分发 → 非阻塞RX缓冲和错误重挂。可先用中断接收证明协议，再根据负载选DMA/IDLE；H7使用DMA时还需处理DMA可访问内存与D-Cache一致性。

初始化位置与现有main/MSP所有权保持一致，不另外定义第二套HAL回调。检索本地HAL的 `HAL_UART_Init`、`HAL_GPIO_Init`、`GPIO_AF8_UART4`、`HAL_UART_Receive_IT`、`HAL_UART_IRQHandler`，对照[UART教学手册](../../../../../20_Knowledge-研发知识库/09_系统学习手册/02_基础外设/03_UART从发送到中断接收.md)理解各步骤。此处为实施清单，不是已完成代码。
