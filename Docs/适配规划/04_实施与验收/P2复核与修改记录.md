## 2. 波特率纠正与依据

用户先回忆“9800 左右”，随后要求从 servo GitHub 代码推导。核对上游 HEAD `aebb357dd4096350ec17f49fdaf23d1b27decb3d`：

| 原工程角色 | 上游证据 | H743 最终映射与配置 |
|---|---|---|
| 蓝牙 | `Project/code/usart.c:24`：huart1=9600 | BLUE → USART3 PB10/PB11，9600 |
| STS 舵机 TTL | `Project/code/usart.c:43`：huart2=1000000；`feetech_sts_bus.c:103/225` 确实使用 huart2 收发 | SERVO → USART2 PA2/PA3，1,000,000、8N1 |
| USB-TTL / VOFA | `Project/code/usart.c:61`：huart3=115200 | HOST → USART1 PA9/PA10，115200 |

因此 9600 属于旧蓝牙，不属于舵机。调查中临时把 SERVO 宏改成 9600，但尚未构建/烧录即根据源码撤回；本轮交付的舵机速率保持 1 Mbps。P1 的蓝牙 115200 则改回源码依据的 9600。板级宏、Core 初始化和 `.ioc` 同步；不向舵机写 EEPROM。源码可以证明原程序使用的速率，设备当前保存值仍以板上只读反馈验证。P3a 补充：以 1 Mbps 为主，若 3 次 PING 无响应则自动回退 9600 等候选速率，只改 MCU 侧，避免再凭记忆争论。

## 3. 本轮修正

| 问题 | 修改及理由 |
|---|---|
| P1 `BoardUart_Transmit` 把 HAL_BUSY/HAL_TIMEOUT 都变成 BOARD_ERROR；STS Port 又全部变成 HAL_ERROR | 增加 BOARD_TIMEOUT，双向保留 OK/BUSY/TIMEOUT/ERROR，避免破坏总线超时/重试语义 |
| UART 资源检查只检查非空，不能发现重复 Instance 或实际速率与 profile 不一致 | `BoardUart_InitAll` 加入重复绑定和波特率校验；App 根据失败点亮故障状态 |
| STS 固定 20 ms TX 超时不适用于以后更低速率的长帧 | Port 按 8N1 线速计算最低发送预算并加 20 ms 余量；当前仍使用 1 Mbps |
| 统一 HAL 在同时定义 F1/H7 目标时可能静默选择分支 | 实际检查 F103/H743 同时选择时报错；新增目标仍需实现对应板级后端 |
| 按键硬件映射和时钟散落在 `bsp_key.*` | 物理 GPIO、有效电平、上下拉和时钟入口集中到 board_config，原手势算法保留 |
| 早期本轮 H1 文档曾把 4 脚写成地 | P1 已纠正；本轮保留正确结论并再次确认：H1-3=GND、H1-4=+5V，不再恢复旧文本 |
| LED 测试文档将 PG7 亮 100 ms 误写成高电平 100 ms | 修正为低电平 100 ms / 高电平 900 ms；PG7 低有效 |

## 4. 新增功能与实际行为

- `board_led.c/.h`：板载 PG7 低有效、外接 PG0/PG1 高有效，角色化设置，非阻塞 1 Hz/2 Hz/5 Hz 模式。
- 上电先熄灭 200 ms，再三次 100 ms 短闪；之后 PG7 每秒亮 100 ms。资源正常时 PG0 常亮，任意按键稳定按住时 PG0 以 5 Hz 闪烁。
- 四路按键 PA0/PB0/PB12/PB13 接入扫描；只记录 `g_p2_key_press_count[4]` 并反馈，不调用夹爪动作。物理去抖后的按下事件累计计数。
- `host_diagnostics.c/.h`：USART1 中断接收 → 255 字节可用环形队列 → 主循环每批最多 32 字节二进制回显。记录 RX/TX、队列溢出、UART 错误、发送失败及重新挂接失败。
- HOST 启动输出一条标识，之后仅回显输入；错误时 PG1 2 Hz 闪烁，错误计数保持至复位。BOARD_BUSY 保留待发数据；超时/错误丢弃当前批并计数，避免部分发送后自动重试生成重复数据。
- `APP_HOST_DIAGNOSTICS_ENABLE=1` 为当前 P2 模式，HOST 回调交给诊断服务。P3 使用 VOFA 前关闭此模式并显式初始化 VOFA，不能同时占用同一 HOST 接收。
- PG0/PG1 加入 `.ioc`；运行时 LED 引脚由 board_config/BoardLed_Init 统一初始化。按键 GPIO 由 Key_Init 根据板级表初始化，`.ioc` 中尚未登记四路按键。`.ioc` 尚未用 CubeMX GUI 重新打开校验。

PG0 亮仅表示 P2 板级资源校验通过，不能解释为“舵机在线”。本轮仍不初始化 STS、夹爪命令、PWM、屏幕、摄像头或 Flash 擦写。
