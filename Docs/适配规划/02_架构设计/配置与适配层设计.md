# 配置与适配层设计 V1.1

最新状态：P2 软件已实现，IAR 0 errors / 1 warning，主机边界测试通过；硬件验收未执行。新增 LED/按键/串口诊断和纠错以 [P2记录](../04_实施与验收/P2复核与修改记录.md) 为准。以下任务和接口约定保留其阶段语境。


状态：P1 已落地 HAL 入口、板级角色表、UART 角色 API、回调路由和 `App_Init/App_Task`（见 [P1实施记录](../04_实施与验收/P1实施记录.md)）；显示/摄像头/存储/GPIO 角色表仍为待实施设计。

## 1. 设计目标与不变量

1. **业务层不出现** `huart1/2/3`、`GPIOA`、`stm32h7xx_hal.h`。
2. **句柄只在一处绑定**：CubeMX 生成 `huart1/2/3`，`board_resources.c` 把它们映射成角色；其他文件只认角色。
3. **引脚只在一处描述**：`board_config.h` 记录角色、端口、引脚、极性、上下拉；`.ioc` 负责生成 AF/时钟/NVIC。
4. **HAL 入口唯一**：所有需要 HAL 类型的文件包含 `platform_hal.h`，由它按目标宏选择 SDK 头。
5. **可裁剪**：关闭屏幕/摄像头/蓝牙/PWM/Flash 时，对应源文件和依赖可以一起不编译。
6. **可替换**：换 H7 型号、换 F4/F1、换固件包时，优先只改 `platform/` 与 `.ioc`，不改 `drivers/` 的协议部分和 `modules/` 的业务。

## 2. 分层与责任

```text
Core / CubeMX          时钟、GPIO/UART/SPI/DCMI/TIM/DMA 初始化、中断入口
App/platform           HAL 入口、板级角色映射、UART/GPIO/LED/时间/存储/总线适配
App/drivers            STS 舵机、PWM 舵机、显示屏、摄像头器件逻辑
App/protocol           主机帧、VOFA 数据编解码
App/modules            夹爪状态、限位、所有权、视觉结果与控制策略
App/app_main.*         初始化顺序、周期任务、错误上报
```

保留现有 App 分层，逐步收拢硬件依赖，不重写 STS 控制和命令代码。驱动通过 Port 调用硬件；业务层不引用句柄或裸 GPIO。

## 3. 建议文件树

```text
App/
├─ HAL_H.h                       # 兼容入口，只转发 platform_hal.h
├─ platform/
│  ├─ platform_hal.h             # 目标选择：H7/F1/...；未知目标直接 #error
│  ├─ board_profile.h            # 选择板型 profile
│  ├─ boards/
│  │  └─ lxb743zi_p1/
│  │     ├─ board_config.h       # 引脚/极性/角色/波特率/功能开关
│  │     ├─ board_resources.c    # 角色 → 句柄/外设实例 的唯一绑定
│  │     ├─ board_uart.c/.h      # 角色化 UART 字节收发（不暴露 HAL 句柄）
│  │     ├─ board_gpio.c/.h      # 角色化 GPIO 读写
│  │     ├─ board_led.c/.h       # LED 状态/闪烁服务
│  │     ├─ board_time.c/.h      # ms 节拍、超时
│  │     └─ board_pwm.c/.h       # 可选：PWM 舵机
│  ├─ uart_router.c              # HAL 回调 → 角色 → 模块，只此一处
│  ├─ display_port.c/.h          # 屏幕后端接口
│  ├─ camera_port.c/.h           # 摄像头后端接口
│  └─ storage_port.c/.h          # 记录读写接口
├─ drivers/
│  ├─ Servo/                     # feetech_sts_*、pwm_servo_*
│  └─ display/                   # LCD/OLED 具体时序
├─ protocol/                     # vofa_protocol、claw_host_protocol
├─ modules/                      # claw_core、shared_state、vision_service
├─ config/
│  └─ feature_config.h           # 业务开关/默认值（保留现有参数）
└─ app_main.c/.h                 # App_Init / App_Task
```

单板阶段不必把 `boards/` 做得很深；保留这个层级是为了第二块板/第二套 SDK 时不再复制业务代码。

## 4. 配置文件划分

| 文件 | 允许配置 | 不承担的职责 |
|---|---|---|
| `App/HAL_H.h` | 兼容入口，转发到 `platform/platform_hal.h` | 不放业务参数 |
| `platform/platform_hal.h` | 按显式目标宏选择 `stm32h7xx_hal.h` 等；未知/多目标编译报错 | 不把 F1 配置伪装成 H7 |
| `platform/board_profile.h` | 选择 `LXB743ZI_P1` 等 profile | 不根据芯片名猜板级接线 |
| `boards/<board>/board_config.h` | GPIO 角色、极性、串口角色、速率、PWM 通道、屏幕/传感器类型 | 不定义句柄，不执行初始化 |
| `boards/<board>/board_resources.c` | 角色 → 唯一外设句柄的绑定 | 不解析夹爪指令 |
| `config/feature_config.h` | 功能开关、默认行为、周期、队列容量 | 不硬编码 `huartX`、Flash 地址 |
| `storage_port.*` + 链接脚本 | 擦写后端、保留区、布局断言 | 业务层不直接调用 FLASH HAL |

CubeMX `.ioc` 管外设 AF、波特率、DMA 和 NVIC；板级配置记录角色及期望值。换 UART 要同步重新生成 `.ioc`、句柄映射和 IRQ；**不能宣称只改一个宏就能完成所有硬件切换**。

## 5. UART 角色绑定（`huart1/2/3` 的收口）

### 5.1 角色表

| 角色 | 板级宏 | CubeMX 句柄 | 引脚 | 首轮参数 | IRQ |
|---|---|---|---|---|---|
| 舵机总线 | `BOARD_UART_SERVO` | `huart2` | PA2/PA3，AF7 | 1 Mbps，8N1 | `USART2_IRQn` |
| 上位机/VOFA | `BOARD_UART_HOST` | `huart1` | PA9/PA10，AF7 | 115200，8N1 | `USART1_IRQn` |
| 蓝牙（可选） | `BOARD_UART_BLUETOOTH` | `huart3` | PB10/PB11，AF7 | 按模块 | `USART3_IRQn` |

### 5.2 接口草案（不是已实现代码）

```c
/* platform/board_uart.h */
typedef enum {
    BOARD_UART_SERVO = 0,
    BOARD_UART_HOST,
    BOARD_UART_BLUETOOTH,
    BOARD_UART_COUNT
} BoardUartRole;

typedef enum {
    BOARD_OK = 0,
    BOARD_BUSY,
    BOARD_ERROR
} BoardStatus;

BoardStatus BoardUart_InitAll(void);   /* 只做角色表校验；实际外设初始化由 CubeMX 生成函数完成 */
BoardStatus BoardUart_Transmit(BoardUartRole role, const uint8_t *data,
                               uint16_t len, uint32_t timeout_ms);
BoardStatus BoardUart_StartRxIT(BoardUartRole role, uint8_t *byte);
void        BoardUart_ClearOverrun(BoardUartRole role);
uint8_t     BoardUart_IsRole(const void *instance, BoardUartRole role);
```

`board_resources.c` 内部（**唯一绑定表**；`board_uart.c` 只使用它，不重复 extern）：

```c
extern UART_HandleTypeDef huart1;
extern UART_HandleTypeDef huart2;
extern UART_HandleTypeDef huart3;   /* 只在本文件 extern */

static UART_HandleTypeDef *const s_uart[BOARD_UART_COUNT] = {
    [BOARD_UART_SERVO]     = &huart2,
    [BOARD_UART_HOST]      = &huart1,
    [BOARD_UART_BLUETOOTH] = &huart3,
};

/* 仅 platform 内部使用；board_uart.c 通过它取句柄 */
UART_HandleTypeDef *BoardResource_GetUart(BoardUartRole role)
{
    if ((unsigned)role >= (unsigned)BOARD_UART_COUNT) {
        return 0;
    }
    return s_uart[role];
}
```

- **`huart1/2/3` 只允许出现在 CubeMX `main.c`（定义）和 `board_resources.c`（extern/绑定）**。
- `feetech_sts_port.c` 里删除 `FEETECH_STS_UART_HANDLE huartX`，改为 `BoardUart_* (BOARD_UART_SERVO, ...)`。
- `bsp_bluetooth.h` 删除 `BLUETOOTH_UART_HANDLE huart1`，`vofa_protocol.h` 删除 `VOFA_UART_HANDLE huart3`，改为角色。
- 如果更习惯“每个串口一个适配文件”，可以保留 `uart1_port.c/uart2_port.c/uart3_port.c` 作为薄封装，但**绑定表仍只能有一份**；不要三个文件各自 `extern huartX` 再各自写一套初始化。
- 回调只保留一个路由入口：`HAL_UART_RxCpltCallback`/`TxCpltCallback`/`ErrorCallback` 在 `uart_router.c` 中按 `BoardUart_IsRole` 分发到模块；CubeMX 的 `stm32h7xx_it.c` 只调用 `HAL_UART_IRQHandler(&huartx)`。
- 由 CubeMX 生成唯一 UART Handle/MSP/IRQ；**删除 `App/bsp/usart.c` 中的 `MX_USARTx_UART_Init` 和第二个 `HAL_UART_MspInit`**。
- 第一阶段保留 IT 接收；后续根据压力测试决定是否加 ReceiveToIdle + DMA，不把 DMA 化当首轮前提。

## 6. GPIO、按键、LED

```c
typedef enum {
    BOARD_GPIO_LED_STATUS = 0,
    BOARD_GPIO_LED_FAULT,
    BOARD_GPIO_KEY1,
    BOARD_GPIO_KEY2,
    BOARD_GPIO_KEY3,
    BOARD_GPIO_KEY4,
    BOARD_GPIO_COUNT
} BoardGpioRole;

void    BoardGpio_Write(BoardGpioRole role, uint8_t logical_on);
uint8_t BoardGpio_Read(BoardGpioRole role);
```

- 端口、引脚、有效电平、上下拉全部在 `board_config.h` 的表中；HAL 类型不进入夹爪业务头。
- 板载 PG7 低有效、外接 PG0/PG1 高有效，由表里的 `active_level` 吸收，业务只传“逻辑亮/灭”。
- 按键扫描保留现有手势算法，输入读取经 `BoardGpio_Read`；按键事件再映射业务命令，避免驱动直接操纵舵机。
- LED 采用语义接口（心跳/状态/故障），非阻塞节拍；具体见 [LED 反馈与引脚测试](../04_实施与验收/LED反馈与引脚测试.md)。

### 6.1 `board_config.h` 的形态（示意）

```c
/* 只允许 platform 层包含 HAL 类型 */
typedef struct {
    GPIO_TypeDef *port;
    uint16_t      pin;
    uint8_t       active_level;   /* 1=高有效，0=低有效 */
    uint8_t       pull;           /* GPIO_NOPULL / GPIO_PULLUP */
} BoardPinConfig;

#define BOARD_PIN_LED_STATUS   { GPIOG, GPIO_PIN_0,  1U, GPIO_NOPULL }
#define BOARD_PIN_LED_FAULT    { GPIOG, GPIO_PIN_1,  1U, GPIO_NOPULL }
#define BOARD_PIN_KEY1         { GPIOA, GPIO_PIN_0,  0U, GPIO_PULLUP }
/* ... 其余角色同理；完整清单以 设备引脚分配.csv 为准 ... */
```

- 这张表是**唯一**记录“角色→端口/引脚/极性”的地方；`设备引脚分配.csv` 是人读的总表，两者由 P1 的一致性检查对照。
- 不建议把 `.ioc` 里的 AF 号再抄一遍到业务头；AF/时钟/NVIC 由 CubeMX 生成代码负责，`board_config.h` 只写角色期望值（例如“这个角色应该是 USART2”）。
- 换板时新增 `boards/<board>/board_config.h` 并在 `board_profile.h` 选择，不改驱动。

## 7. 显示、摄像头、存储

- `display_port.*`：初始化、绘图/提交、忙状态。现有 `screen_display.c` 无条件包含 `OLED.h`，且 `OLED.c/h` 不在 App/Core；P1 先关掉 `SCREEN_ENABLE_OLED` 或拆出 LCD 后端，不能只改宏而保留缺失头文件。
- `camera_port.*`：初始化、启动/停止、帧就绪、Acquire/Release、错误计数；中断只报告帧事件。先单帧，再连续采集/双缓冲。
- `vision_service.*`：输出目标坐标/置信度/时间戳；夹爪控制通过有效期、模式和状态检查后才消费。
- 图像区域、分辨率、像素格式、刷新率、超时和缓存策略在 profile 中约定。
- 限位持久化：H743 的 Bank/扇区、擦除粒度、编程单位、地址和链接 ROM 排除区按本地 H7 HAL/芯片资料重新核对；**不复用 F103 的 1 KB 页和 `0x0800F800/0x0800FC00`**。开发顺序：RAM/禁持久化后端通过业务回归 → 保留区设计 → 链接 map 校验 → H7 Flash 后端 → 断电恢复和损坏记录测试。

## 8. 单一事实来源与一致性

同一件事不要在两处各写一遍：

| 信息 | 唯一来源 | 派生/检查 |
|---|---|---|
| 外设 AF、时钟、NVIC、DMA | `.ioc` + CubeMX 生成代码 | `board_config.h` 只写角色期望值 |
| 引脚角色、极性、上下拉 | `board_config.h` | 与 [设备引脚分配.csv](../03_硬件规划/设备引脚分配.csv) 对照 |
| 句柄绑定 | `board_resources.c` | `BoardUart_*` 查表 |
| 业务默认值 | `feature_config.h` | 不写硬件地址 |
| 存储布局 | 链接脚本 + `storage_port` | 编译期/启动断言 |

建议 P1 加一个轻量检查（脚本或人工清单）：

1. `rg "huart[123]" App` 只应命中 `board_resources.c`。
2. `rg "stm32f1xx|stm32h7xx" App --glob '!platform_hal.h'` 应为空；业务头只包含 `<stdint.h>`。
3. `.ioc` 中的引脚集合与 `board_config.h`/CSV 逐项对照。
4. 关闭某功能后，对应源文件从工程移除，链接不报未定义。

## 10. 后续移植清单

更换 MCU/SDK 时集中处理：`platform_hal.h` 目标选择、CubeMX 生成配置、board profile、外设资源绑定、IRQ 路由、时钟与 PWM 计数、内存链接与缓存策略、Flash 后端。协议编解码、夹爪业务和按键手势尽量保持不变。SDK 厂商目录保留原生结构，通过版本登记替换，不在业务源码散布 SDK 路径。
