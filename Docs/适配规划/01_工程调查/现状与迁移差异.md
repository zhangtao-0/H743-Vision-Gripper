# 工程现状与迁移差异

## 调查范围与基线

- 目标：`H743/project/H743_VisionGripper.ioc`，STM32H743ZIT6、LQFP144。
- 工程：`project/EWARM/H743_VisionGripper.ewp`，CubeMX 目标 EWARM V8.50；本机发现 IAR 9.2 安装，兼容性以实际构建为准。
- SDK 声明：STM32Cube FW_H7 V1.13.0；需要在实施阶段登记实际 HAL 文件版本，不能仅凭 `.ioc` 认定所有文件一致。
- 当前时钟设计：HSE 25 MHz、SYSCLK 400 MHz、AHB 200 MHz、APB 100 MHz；实际晶振与板型待确认。
- 当前 H743 根目录没有 Git 仓库，未执行初始化、提交或推送。正式修改前先建立可恢复源码快照或采用用户现有版本管理方式。
- 上游：[zhangtao-labs/servo](https://github.com/zhangtao-labs/servo)，本轮通过 Git 获取 HEAD：`aebb357dd4096350ec17f49fdaf23d1b27decb3d`。临时克隆未覆盖任何本地工程文件。

## 本地与上游对照

本地 App 共 33 个 `.c/.h`：同名候选按字节比较，11 个完全相同、17 个不同、5 个本地新增。不同可能含换行、编码、注释或逻辑变化，不能把数量直接解释成业务改动数量。逐文件路径与 SHA-256 见 [源码差异清单](../05_调查证据/源码差异清单.json)。

本地新增包括 `HAL_H.h`、`feetech_sts_port.c/.h`、`pwm_servo_control.c/.h`；本地已把部分总线收发转到 Port 层，这是可以继续完善的基础。上游 `Project/user/main.c` 中的初始化和任务调度可作为恢复业务接线的参考，但时钟、UART、GPIO、TIM 和存储实现应以 H743 目标工程重新生成或实现。

已经确认的行为差异：本地将原先两路按键扩展为四路；本地配置及控制头中移除了上游的部分 STS/PWM 后端选择字段，却另外保留了 PWM 控制文件。因此不能直接把上游默认 STS+PWM 行为带回目标工程。Port 改写中还有两处静态问题：`feetech_sts_bus.c:811` 发送参数用了未定义的 `frame/len`，应结合该函数的 `packet/packet_len` 修复；`StartReceive` 提前返回后保留了旧的不可达代码。`feetech_sts_bus.c` 也尚未显式包含 Port 接口头，需在修复中一起核查。

上游另有 `Libraries/SDK/FeetechSCS`。当前 App 使用自身 `feetech_sts_*` 总线、命令和控制实现，不能为了“补齐”而直接加入另一套总线库；先核查实际依赖及许可，避免两套协议栈同时抢占串口。

## 已核实的迁移问题

| 问题 | 源码证据（相对 project） | 影响与处理 |
|---|---|---|
| HAL 入口尚未统一 | `App/HAL_H.h` 已指向 H7；多个 App 头仍直接包含 `stm32f1xx_hal.h` | 业务及驱动入口逐步统一；纯协议层优先去除 HAL 类型依赖 |
| 舵机句柄占位 | `App/drivers/Servo/feetech_sts_port.c` 定义 `FEETECH_STS_UART_HANDLE huartX` | 不能编译；用板级角色映射提供句柄 |
| USART1 定义重复 | `Core/Src/main.c` 与 `App/bsp/usart.c` 都定义 `huart1`、USART1 初始化；两份 MSP 文件也实现 UART MSP | 全部纳入构建时会产生符号冲突；由 CubeMX 一处生成外设和 MSP |
| 构建搜索路径未覆盖 App | EWP 的 `CCIncludePath2` 当前只有 Core、HAL、CMSIS | App 已列入工程但内部跨目录头无法正常解析；统一维护路径并清理重建 |
| 缺少 H743 UART 中断接线 | `Core/Src/stm32h7xx_it.c` 无 USART1/2/3 Handler；目标 MSP 仅配置 USART1 GPIO | 配置 UART IRQ/NVIC 并接入 HAL；回调只保留一个路由入口 |
| 业务尚未接入 | H743 `main()` 的 USER CODE 区和循环为空 | 新增 App_Init/App_Task，依照依赖恢复初始化与调度 |
| 定时器配置仍是旧方案 | `App/bsp/tim.c` 分频 `64-1`，PA6/PB1 PWM；GPIO 缺少 H7 对应 AF 设置 | 按实际 TIM kernel clock 计算 1 MHz 计数；不能按主频比例盲改 |
| PWM/显示相关 HAL 未启用 | `Core/Inc/stm32h7xx_hal_conf.h` 的 TIM、SPI、DCMI 模块未启用 | 根据实际功能同步 `.ioc`、HAL 选项和工程源文件 |
| 旧 Flash 后端不适用 | `claw_limit_storage.*` 使用 1 KB 页、`0x0800F800/0x0800FC00`、PAGES/HALFWORD | 这些地址位于 H743 当前链接 ROM 范围，不能沿用；先换成 RAM/禁持久化后端，再规划 H7 后端和保留区 |
| 屏幕驱动依赖缺失 | `screen_display.c` 无条件包含 `OLED.h`，App/Core 未见该实现 | 单改关闭宏不足以解决全部静态依赖；拆出显示后端后接入实际 LCD 或 OLED |
| 原串口职责硬编码 | USART1 蓝牙 9600、USART2 STS 1 Mbps、USART3 VOFA 115200；回调按 Instance 分支 | 目标已生成 USART1=115200，与旧蓝牙默认不同；需按角色重新统一 |
| VOFA 数据格式须确认 | `vofa_protocol.*`、`claw_host_protocol.*` 使用已有官方/扩展帧 | 不默认等同于 JustFloat/FireWater；先保留兼容，再由配置选择可视化协议 |

## 厂商例程盘点与采用方式

这些是用户提供的“官方参考历程”目录中的板卡例程，不把它们全部认定为 ST 官方通用模板。保留原件，提取芯片/器件初始化依据，在目标 BSP 中重新组织。

| 例程 | 采用阶段 | 适配重点 |
|---|---|---|

| 【2】串口打印测试 | 第一批 | USART1 PA9/PA10、115200；日志与 VOFA/舵机链路隔离 |

## 实际构建诊断

在临时源码副本使用 IAR Command Line Build Utility 9.2.2.10770、ARM Compiler 9.40.1.364，构建配置 `H743_VisionGripper`；结果退出码 1，**51 个错误、15 个警告，构建失败**。已运行到实际源文件编译，主要报错包括缺少 `stm32f1xx_hal.h`、无法找到 `HAL_H.h`/跨目录业务头、TIM 类型与宏未定义。没有生成可交付固件，也未执行下载。

这些是首轮构建暴露的问题；后续修复后还可能显露链接重复定义和其他编译错误。静态调查列出的风险不全部已经由编译器验证。完整日志与复现命令见 [构建与证据说明](../05_调查证据/README.md)。

## H7 内存设计要单独处理

当前 IAR 链接脚本将普通 RAM 放在 `0x20000000–0x2001FFFF`，并未为图像缓冲定义独立 AXI SRAM 段。摄像头例程直接使用 `0x24000000`，并启用 DCache；不能把这一地址简单作为普通全局数组替代，也不能只复制 MPU 配置。

240×240 RGB565 单帧为 115,200 字节、双缓冲为 230,400 字节；须为 DMA 可达 RAM 建专用段、检查链接 map，定义 CPU/DMA 缓冲所有权和 Cache 操作。优先采用非缓存帧缓冲区域或经过验证的 32 字节边界缓存维护策略。摄像头采集与 LCD 刷新不得长时间阻塞夹爪任务。
