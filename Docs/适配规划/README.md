## 接续状态：P2 软件已实现（2026-10-20）

已重新读取 P1，并继续完成三路 LED、四路按键与 HOST 二进制回显诊断；IAR 为 **0 errors / 1 warning**，主机边界测试通过，**板上测试未执行**。以 [P2复核与修改记录](04_实施与验收/P2复核与修改记录.md) 为最新状态，下文 P1 与历史计划保留作阶段证据。

上游代码明确：**舵机 USART2=1,000,000；旧蓝牙=9600；上位机=115200**。H743 角色映射为 SERVO→USART2、BLUE→USART3、HOST→USART1。P3a 以 1 Mbps 为主，3 次无响应后自动回退 9600 等候选速率；只改 MCU 侧，不修改舵机 EEPROM。

当前 HEX 是 **P3 完整版**：上电先只读探测/自动波特率（ID=0、270°），ONLINE 后接入原有 command/control；不按键、不发帧不会动作。板上动作尚未验证。

## 当前结论

1. **以本地代码为适配主线**，保留用户改动；GitHub 上游只作对照，不整包覆盖。2026-10-20 核对上游 `HEAD=aebb357dd4096350ec17f49fdaf23d1b27decb3d`。
2. **P1 已完成（构建层面）**：补 App include、统一 HAL 入口、删除重复 `huart1`/MSP、建立 `App_Init/App_Task`，IAR 从基线 **51 errors / 15 warnings** 变为 **0 errors / 1 warning**。
3. **引脚方案已选定；`.ioc` 已补 USART2/3、NVIC、PG0/PG1**；P2 已接 LED 与四路按键扫描，按键由板级表/Key_Init 初始化；SPI6 实体、DCMI 和 TIM3 后续补齐。
4. **H1 排针定义已更正**：H1-3 是 GND，H1-4 是 +5V（旧版文档写成 H1-4=GND，属于危险错误）。VOFA 的 USB-TTL 地必须接 H1-3。
5. **解耦的核心是“角色化”而不是“只换头文件”**：`huart1/2/3` 只在 `board_resources.c` 中绑定，业务层用 `BOARD_UART_SERVO/HOST/BLUETOOTH`，GPIO 用角色表，换板只改 `platform/` 和 `.ioc`。
6. **推荐节奏**：P1 最小系统编译通过（已完成）→ P2 LED + USART1（已完成）→ P3 舵机只读/动作 + 按键 + VOFA（软件已接入，动作待板上验证）→ P4 持久化 → P5 屏幕 → P6 摄像头 → P7 视觉闭环。不要同时打开屏幕、摄像头和舵机。
