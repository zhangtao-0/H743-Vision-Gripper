# 屏幕页面、业务动作与按键映射怎样建立

## 一、三个层次分开理解

[ui_core.c](../../../project/App/modules/ui/ui_core.c)管理页面栈、光标、草稿、确认取消和快捷往返，不操作HAL；[ui_port.c](../../../project/App/modules/ui/ui_port.c)将统一的参数和动作接口映射到设备服务；[ui_service.c](../../../project/App/modules/ui/ui_service.c)承担运行集成与显示协作。字体和绘图负责“画出来”，不应在绘图函数里直接发舵机指令。

| 想增加的内容 | 接入位置 | 是否需要新增页面 |
|---|---|---|
| 普通可编辑参数 | UiPort名称、读写、数量 | 通常不需要，参数列表和工厂值列表按parameter_count枚举 |
| 常用执行操作 | 动作名称、运行分支、分组、command_count | 通常放入现有设备分类，复用确认页 |
| 实际状态 | StatusLine对应设备页，必要时扩展显示模型 | 先检查现有行数和页数是否容纳 |
| 指令分类打印 | 帮助目录与生成头，help_count | 屏幕帮助页已有枚举入口 |
| 完全新的交互页面 | UiPage、Count、Event、View、页面路径测试 | 需要明确进入、退出和快捷恢复行为 |

新增普通参数后，不要再给屏幕建一份变量。菜单读取ParamRead，编辑时保存original与draft；下一项加步长、上一项减步长，越界饱和；确认重新读值并调用ParamWrite，取消只丢弃draft。屏幕离线显示OFFLINE属于状态反馈，不要为了“能调”删掉业务门控。

## 二、增加一个执行选项

当前共有20个动作、5个分类（夹爪、电机、摄像头、本地PWM、系统）。`CommandName`提供名称，`CommandGroup`决定分类，`UiPort_RunCommand`决定实际执行。增加动作需要同时更新这些内容和`ops.command_count`。

例如未来增加“开始视觉自动夹取”：先做业务状态机，定义开始、取消、失败与超时；再追加动作ID并分入夹爪分类。当前自动夹取选项返回未实现，不能把提示文字改成成功冒充功能完成。执行页经过确认页，默认选中CANCEL；失败后也回到取消选中状态。

上位机动作与屏幕动作宜复用业务入口。现有`UiPort_RunCommand(id,source)`区分SCREEN、HOST、USB，并向STS传递对应控制来源；不要从串口调用一个假装来自屏幕的分支。新命令还应有明确回复，执行打印帮助不能触发动作。

图像查看菜单有自己的一组动作索引；如果调整现有动作编号，要核对`UI_IMAGE`和`UI_VIEW`的索引映射。更稳妥的是保留既有编号再追加。屏幕旋转与相机旋转/镜像仍是独立配置。

## 三、物理按键先定义，上位机模拟同一含义

[按键表](../按键映射.csv)是当前接线、短长按和模拟命令的对照。KEY1/A0与KEY2/B0是舵机业务键；KEY3/4是菜单键；EC11按钮用于电机手势。这里不是给每个菜单项目分配一根GPIO。

| 物理操作 | 当前模拟文本 | 效果 |
|---|---|---|
| KEY3短按 | `@key 3 tap` | 下一项或加值 |
| KEY3长按 | `@key 3 hold` | 上一项或减值 |
| KEY4短按 | `@key 4 tap` | 进入或确认 |
| KEY4长按 | `@key 4 hold` | 返回或取消 |
| KEY3+KEY4组合 | `@keys 12 100` | 观测页快捷进入/返回 |
| EC11正转一格 | `@knob 1` | 请求目标速度增加一格，并非伪造霍尔反馈 |

`@keys`中的12是位掩码，KEYn对应`1<<(n-1)`，所以KEY3与KEY4是4+8。不是KEY12。具体保持时长及输入模式见[操作手册](../01_上位机模拟与按键操作.md)；tap/hold发送后仍由去抖和手势时序处理，不能以串口一收到就期望屏幕同步跳转。

扩展实体键要检查：空闲引脚与电平→板级绑定→GPIO输入/上下拉→BSP扫描去抖→输入来源合并→手势事件→业务/菜单。扩展上位机模拟必须沿同一事件通道，不单独发明第二套确认逻辑。physical模式只接受实体操作；remote和mixed按既有合并规则使用，切换或断线要清理模拟保持。

## 四、快捷页不是强制覆盖当前页面

当前UI_SHORTCUT在非观测页保存完整页面路径并直接建立“主页→观测页”；在快捷观测页再触发则恢复原路径。常规返回会退出并清理快捷记录；常规进入也可以使用同一观测页。不能只保存一个页面编号，否则光标、参数草稿和深层返回关系会丢失。

新增页面测试应覆盖：列表滚动、只读参数、编辑取消、编辑期间上位机改值、动作取消/执行失败、快捷进入再恢复、在观测页常规返回。当前页面数、列表行数、字符串缓冲区是有限的；新增长名称先看实际渲染，不能只验证C编译通过。新增中文文字还需核对字体生成流程和字模覆盖。
