# 参数表、屏幕映射、帮助和VOFA配置怎样同步维护

## 一、每份资料负责什么

| 资料或代码 | 它记录什么 | 增加内容时怎样维护 |
|---|---|---|
| ui_port.c | 参数真实名称/元数据/写入与动作分组 | 先实现并核对业务，再维护表格 |
| [参数映射.csv](../参数映射.csv) | ID、名称、旧名称、工厂值、范围、权限、get/set模板、旧F2编号、备注 | 一参数一行，单位放名称或备注；没有旧F2映射就留空 |
| [按键映射.csv](../按键映射.csv)与[JSON](../按键映射.json) | 引脚、手势、模拟指令、组合掩码、业务门控 | 两份都修改；新实体键还需更新BSP/板级绑定与测试 |
| [指令帮助目录.json](../指令帮助目录.json) | 分类、可执行命令示例与独立说明行 | 它是生成console_help.h的输入；不要只改生成头 |
| [VOFA快捷指令.csv](../VOFA快捷指令.csv)与[JSON](../VOFA快捷指令.json) | 分类、名称、发送模式、命令、准确字节、是否自动执行 | 两份手动同步；不是帮助生成脚本自动生成的 |
| [文本指令目录.json](../../指令手册/04_维护与证据/文本指令目录.json) | 解析器支持的语法变体 | 增加新语法才追加；通用param增加ID通常不增加语法种类 |
| [手册清单.json](../../教学手册/05_维护与证据/手册清单.json) | 教学文档登记与导航责任 | 新增教学Markdown登记，修改既有文件不重复登记 |

参数表当前字段为`id,ui_name,legacy_name,compiled_default,range,text_write,get,set_template,legacy_F2_id,notes`。`set_template`可写VALUE占位，给人阅读；真正给上位机快捷发送的例子必须用具体安全数值。屏幕映射由参数ID→名称/Read/Write和动作ID→名称/分组/Run构成，不是把CSV下载进屏幕，修改CSV本身不会改变固件。

## 二、编码和协议也属于映射

ASCII文本发送要带回车或换行，快捷表统一ASCII+CRLF，末尾实际字节0D 0A。例如`@status`对应40 73 74 61 74 75 73 0D 0A。不要发送字符“\r\n”代替换行。

HEX模式发送真实字节，不能把带空格的十六进制字符串当ASCII。F5尾字节模板与STS普通帧的校验规则不同；旧二进制参数ID不因文本参数新增而自动改变。表格应标清端口、波特率、发送模式和单位，尤其是千分之一缩放和角度浮点。

帮助输出的目标是让用户复制命令再发送。`@help`先列分类，`@help params`打印参数相关命令；`@param list`按实际值生成可复制的get/set行。屏幕帮助选项调用同一分类打印入口，不应在屏幕铺满每条串口语法，也不应打印时自动执行。说明用独立#行，命令行保持可直接复制；没有新语法时优先复用通用param，避免无意义增加入口。

## 三、维护操作顺序

在H743目录执行以下命令。生成器会写帮助头，因此应先检查JSON，再生成，再查看差异；只核对时使用--check。

```powershell
python Tools/generate_console_help.py
python Tools/generate_console_help.py --check
python Tools/verify_input_mapping.py
python Tools/verify_command_manual.py
python Tools/validate_learning_library.py
```

当前输入映射核验器明确断言9类帮助、25个参数及既有引脚；增加参数后需要同步它的预期，而不是删掉断言让所有数据无条件通过。核验器检查CSV与JSON部分字段、命令字节、参数名和编译帮助一致，但并没有证明所有备注、权限和UI路径语义正确，仍需人工逐项追踪。

若生产代码有改动，还需按实际范围运行相关主机测试，如`Tools/run_ui_tests.py`、`Tools/run_motor_tests.py`、`Tools/run_integration_host_tests.py`，以及`Tools/build_integrated.ps1`的现有三配置构建流程。先阅读脚本参数与已有构建记录，不能凭印象指定不存在的IAR配置。

生产基线和函数定位用于发现漂移。新增代码应在审查实际差异后按既有证据流程更新基线/定位；不要为了消除报告报错，把未审查的全部现状直接登记为正确。本轮没有修改生产文件，因此原基线仍应完整通过。

## 四、验收矩阵

| 层次 | 至少验证 | 通过说明什么 |
|---|---|---|
| 表格与链接 | 名称/编号/单位一致，字节与命令一致，链接可打开 | 教材可导航、映射无明显机械错误 |
| 参数服务 | 最小/最大/越界/溢出，停机与运行，离线与维护，读回真实值 | 业务写入和权限符合契约 |
| UI | 草稿取消不写入，确认成功，旧值冲突拒绝，列表末项与快捷返回 | 交互状态机正确 |
| 保存 | save/load/复位、旧记录回退、CRC/半写/删除记录 | 格式与恢复软件逻辑正确 |
| 目标构建 | 本项目三个实际配置编译与链接 | 固件在这些配置可构建 |
| 实物 | 上位机发送→屏幕同步→设备响应→复位后读回 | 对应硬件和固件版本下实际闭环成立 |

软件测试、编译和文档核验不能替代最后一行。对电机仍须保持无H桥时禁用功率输出；对舵机需要在线、有效机械范围及实际供电。记录具体固件版本、端口、发送字节、反馈和未验证项。
