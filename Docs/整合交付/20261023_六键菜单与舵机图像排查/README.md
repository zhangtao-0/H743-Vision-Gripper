## 舵机结论与纠错记录

原仓库默认ID1、1Mbps，广播254；ID0不是广播。H743默认从0纠正为1，统一引用板级配置。本轮新增@servo status、@servo scan BAUD、@servo angle DEG，旧F5/官方帧保留原格式，详见[命令说明](../../指令手册/01_文本控制台/05_舵机诊断与角度等效入口.md)。

用户厂商软件USB直连可运动，截图ID1/1Mbps、型号STS3215、反馈10.3V，状态出现“过压欠压”字样；V1输入11.5V。该结果不证明舵机额定范围或转接板降压电路。见[原截图](厂商软件ID1与电压状态.png)和[用户报告](厂商软件用户验证.json)。

此前按通用交叉方式指导PA2→板RX、PA3→板TX，未核实该板丝印定义，这是接线指导错误。本实物板按MCU侧命名，用户恢复同名PA2→板TX、PA3→板RX后，3次PING新增18个接收字节；交叉时无新增。见[交叉接法只读结果](厂商验证后恢复接线只读探测.json)、[同名接法只读结果](同名接线ID1只读探测.json)。这18字节尚不足以证明是完整真实应答。

代码另有两处诊断缺陷：ERROR=1的PING状态包恰好与请求相同，会被发送回显过滤器丢掉；P3又把非零ERROR当格式错误。已修复为保留歧义PING候选、继续READ身份确认，完整读取ID/型号/波特率/限位后才最终在线；纯回显不会验证身份。设备告警保留为last_error，非零时不会自动接入运动栈，新增角度命令也不绕过错误状态。未修改舵机EEPROM或保护阈值。

此前因ST-Link DEV_CONNECT_ERR暂停烧录的历史日志保留。用户恢复连接并调整舵机电压检测阈值后，本修订版已烧录、独立读回通过，ID1/1Mbps真实反馈恢复，error=0。详见[烧录后实物验收](烧录后实物验收.md)，本次未发送机构运动指令。

## 电脑预览与训练

COM11已确认为H743原生USB CDC；旧固件@video on后6.19秒收到7帧、CRC错误0。见[USB实测](上一版实物USB诊断.json)和[末帧](实物USB最后一帧.png)。新建双击[启动预览.cmd](../../../Host/vision_gripper/启动预览.cmd)，自动识别CDC并开启视频；XCAM当前没有本项目H743IMG1协议适配，打开串口本身不会显示。

按顺序阅读[从USB到第一张图](../../视觉识别与抓取/10_零基础从接线到第一张图.md)和[采集到训练及手持测试](../../视觉识别与抓取/11_从图片到训练的逐步教程.md)。预览、采集不需要模型/GPU；标注、数据划分、训练、测试与加载best.pt才是后续深度学习步骤。当前未训练自定义权重，也未实现自动三维抓取。

RTX4060 Laptop约8GB已确认，但项目环境复查仍是torch2.14.1+cpu、CUDA=False。两次官方cu126下载哈希不符，保留[首次失败](CUDA安装_首次校验失败.log)、[重试失败](CUDA重试.log)、[复查](训练环境复查.json)；没有绕过校验或假报GPU就绪。可先用CPU训练，后续需重新完成正确CUDA包安装。
