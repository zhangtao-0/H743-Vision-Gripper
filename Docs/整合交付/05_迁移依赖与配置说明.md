# SDK、配置、资源和后续移植

## 当前依赖

项目 `.ioc` 声明 CubeH7 固件包 V1.13.0；本轮实际读取 `stm32h7xx_hal.c` 的驱动版本为 **HAL 1.11.6**。包版本与 HAL 驱动版本不是同一个编号。所有新增 HAL 源均来自 `project/Drivers`，没有纳入厂商示例的旧 HAL 或另一套 CMSIS。

LCD/Camera/QSPI/SD 器件逻辑、寄存器表、FatFs 和 USB Device 中间件提取自用户提供的本地例程。具体来源和哈希逐文件记录，后续替换 SDK 时可区分厂商器件逻辑和 ST HAL。

## 修改配置的位置

| 内容 | 位置 |
|---|---|
| 唯一 HAL 选择入口 | `App/platform/platform_hal.h` |
| UART 角色→句柄 | `App/platform/board_resources.c` |
| 角色速率、ID、LED/KEY | `App/platform/boards/lxb743zi_p1/board_config.h` |
| 设备引脚、AF、SPI/SD/PWM 参数 | 同目录 `board_devices.h` |
| 功能开关、传感器选择、预览尺寸/条带、测试区/持久化地址 | `App/config/integration_config.h` |
| 原夹爪业务参数 | `App/config/feature_config.h` |
| PLL2、SPI6/QSPI/SDMMC/USB 内核时钟、RTC、PWM、MPU | `App/platform/board_peripherals.c` |
| UART MSP/IRQ、主系统时钟 | `Core`；CubeMX 负责这部分 |
| 器件 MSP/寄存器初始化 | `App/vendor` 的适配副本；板级宏由 board_devices.h 注入 |
| 段放置、Flash 保留区、栈/堆 | `EWARM/stm32h743xx_flash.icf` |

迁移到其他引脚时同步修改对应 GPIO 时钟与 BSP，不宣称任意外设都能只改一个宏完成迁移。变更 UART 时，角色绑定、`.ioc` 的 AF/NVIC、速率与生成代码必须一致。

## 内存边界

- 普通数据/栈/堆：DTCM `0x20000000–0x2001FFFF`；栈 8 KB、堆 4 KB。
- 图像：`.camera_dma` 在 AXI SRAM `0x24000000–0x2407FFFF`，240×240 RGB565 为 115,200 字节，32 字节对齐、非缓存；DMA2 不接收 DTCM 缓冲指针。
- USB PCD DMA 关闭，传输使用当前 CDC 队列和端点缓冲，不依赖 DTCM 的 DMA 可达性。
- QSPI：0x90000000 开始 8 MB 只读、不可执行窗口；进入映射与间接读写互斥。
- 内部限位：`0x081C0000`、`0x081E0000`，两个 128 KB 扇区；链接 ROM 截止 `0x081BFFFF`。记录每次编程 32 字节，旧记录在新记录写好之前保留。
- 外部 QSPI 测试专用最后 4 KB；文件系统测试只新建自己的文件，不启动格式化。

## 调度与控制边界

摄像头采集/显示采用快照和小条带，支持与原控制循环协作；仍须在板上观察 `loopmax` 和通信错误率。默认画面预览不是目标识别算法。AF、SD/QSPI 写入和设备重新初始化属于维护操作，未设计成运动中的异步后台作业。

两路 PWM 默认不随上电产生输出；原虚拟按键帧已接回。`BOARD_KEYS34_CONTROL_PWM=0` 时实体 KEY3/4 控制预览/状态，设置为 1 时改为原 PWM 两路按键用途。

## CubeMX 与 SDK 升级

`.ioc` 管理 Core、主时钟、UART 和基础 GPIO；厂商外设由独立 BSP 初始化，不依赖每份示例的 main。新增内存配置和 IRQ 入口保存在 USER CODE 调用/区域中，IAR 工程负责器件和中间件源文件列表。

本轮未运行 CubeMX GUI 重新生成，所以不能声称已经验证“一键重新生成不改变任何行为”。重新生成前保存快照，生成后检查 App 调用、三路 UART 角色/速率、中断、EWP 文件清单、HAL module 开关与链接脚本保留区。SDK 升级后执行三个构建配置和主机测试，再执行板级验收。
